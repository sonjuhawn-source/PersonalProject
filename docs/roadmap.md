# 개발 로드맵 — 1차 (6주 / 약 120시간)

> 상태: **초안** · 최종 수정 2026-07-28
> 전제: 1인 · 주 20시간 · 6주 = **총 약 120시간** · 우선순위는 **완성된 루프**

관련: [GDD](GDD.md)

---

## 원칙

1. **매주 끝에 플레이 가능한 상태를 유지한다.** "코드는 짰는데 아직 실행 안 됨" 주를 만들지 않는다.
2. **잘라내지 말고 이연한다.** 1차에 안 넣는 것도 붙일 자리는 남긴다 (GDD 9장 확장 지점).
3. **주별 시간을 초과하면 기능을 미루지, 다음 주를 당겨 쓰지 않는다.** 밀린 주는 복구되지 않는다.

### 120시간의 현실

4개월 계획을 6주로 압축한 게 아니라 **범위 자체를 다시 잡은 것**이다.
가장 아픈 지점은 **손맛 검증에 쓸 시간이 1주밖에 없다**는 것 — 원래는 여기서
"재미없으면 머문다"고 했지만, 완성된 루프를 우선하기로 했으므로 W1은 **타임박스**로 운영한다.
1주 안에 만족스럽지 않아도 W2로 넘어가고, 감각 조정은 W6 버퍼에서 다시 손댄다.

---

## W0 — 사전 준비 (개발 기간 외, 2~3시간)

- **유료 에셋 확정 및 임포트** (GDD 미결정 #1)
  최소: 캐릭터 1 + 적 3 + 무기 이펙트 3 + 타일셋 1 + 타격음
- `Assets/Imported/` 에 **Git LFS 먼저 설정**한 뒤 커밋
- **Unity Localization 패키지 설치** (`com.unity.localization` — 현재 미설치)
  → 로케일 2개 생성: 한국어 / 영어
- 폴더 구조 / 어셈블리 정의 잡기

> 에셋 탐색을 W1 이후로 넘기면 일정이 반드시 무너진다. 여기서 끝낸다.

## W1 — 전투 코어 (20h)

| 작업 | 시간 |
|---|---|
| 액션 맵에 키보드 + 게임패드 바인딩 두 벌 등록 | 1h |
| 플레이어 이동·점프 (코요테 타임, 점프 버퍼, 선입력) | 5h |
| 평타 콤보 + 히트박스 | 5h |
| 히트스탑 / 넉백 / 화면 흔들림 / 피격 무적 | 5h |
| 더미 적 1종 (예고 → 공격 → 경직) | 4h |

**주말 산출물:** 적 하나를 때려눕힐 수 있다. 아트는 에셋 그대로, 레벨은 평지 하나.
**결정:** 2단 점프 유무 (미결정 #3)

## W2 — 무기 교체 시스템 (20h)

이 게임의 정체성. **가장 중요한 주.**

| 작업 | 시간 |
|---|---|
| 무기 SO 데이터 + 런타임 래퍼 구조 | 5h |
| 슬롯 2개 + 스왑 (대시 + i-frame + 쿨타임) | 5h |
| 대기 무기 쿨타임 회복 | 2h |
| 무기 3종 (대검 / 단검 / 마법서) — 평타 + 스킬 2종씩 | 8h |

**주말 산출물:** 무기 2개를 번갈아 쓰며 싸운다.
**결정:** 스왑 공격 판정 (미결정 #2), 동일 무기 2개 허용 (미결정 #4)

> 여기서 `rarity` 필드 등 이연 항목의 **자리만** 만들어 둔다 (값은 안 쓴다).

## W3 — 방 / 스테이지 구조 (20h)

| 작업 | 시간 |
|---|---|
| 방 프리팹 구조 + 메타데이터(타입·난이도) | 4h |
| 방 타입 **핸들러 매핑** (전투/보상/보스) | 3h |
| 방 전환 · 스테이지 진행 관리 | 4h |
| 방 프리팹 6~8개 제작 | 5h |
| 적 3종으로 확충 (돌진 / 원거리 / 방패) | 4h |

> 적 AI는 GDD 9.1 구조로 잡는다. `IPatternSelector` 분리를 여기서 해두면
> W5 보스가 데이터 작업이 되고, 후속 BT 전환도 판단 층 교체로 끝난다.

**주말 산출물:** 방을 연달아 클리어하며 스테이지를 진행한다.

## W4 — 로그라이크 루프 (20h)

| 작업 | 시간 |
|---|---|
| 보상 3택 1 (무기 / 유물) | 5h |
| 유물 시스템 — 이벤트 훅 구독 구조 | 5h |
| 유물 **6종** (스왑 연동 3종 포함) | 4h |
| 런 시작 / 사망 / 재시작 + `RunState` / `RunResult` | 6h |

**주말 산출물:** 런 한 판이 처음부터 끝까지(보스 제외) 돌아간다.

> `RunState` 를 **순수 데이터 한 덩어리 + RNG 시드**로 잡는 게 이 주의 핵심이다 (GDD 11.3).
> 여기서 흩뜨리면 후속 "이어하기"가 전면 재작성이 된다. 런 종료 시 `RunState` → `RunResult` 정산.

## W5 — 보스 + UI (20h)

| 작업 | 시간 |
|---|---|
| 보스 1종 (패턴 3~4개, 페이즈 2) | 10h |
| UI — 체력, 무기 슬롯·쿨타임, 보상 선택, 결과 화면 | 7h |
| 일시정지 + 설정 화면 (볼륨 / 해상도 / 언어) + JSON 저장 | 3h |

**주말 산출물:** 시작 → 전투 → 보상 → 보스 → 결과. **루프 완성.**

> 보스는 일반 적과 **같은 상태머신 틀**로 만든다 (GDD 9.1). 보스 2 추가 시 재작성을 피한다.
> UI 문자열은 처음부터 **String Table 키로 참조**한다 — 하드코딩하면 나중에 전부 찾아 고쳐야 한다.

## 일정이 밀릴 때

**추가 시간을 만들지 말고 아래 순서로 범위를 줄인다.** (GDD 8장과 동일)

1. 유물 8종 → 5종
2. 방 프리팹 6~8개 → 4개
3. 적 3종 → 2종
4. 보스 페이즈 2 → 1

**무기 교체 시스템(W2)과 보스 존재 자체(W5)는 지킨다.** 이 둘이 빠지면
포트폴리오로서 보여줄 게 없어진다.

## 1차 이후 (후속 작업)

1차가 완성된 뒤 GDD 8장 "후속" 열을 순서대로 채운다. 확장 지점을 지켰다면
대부분 **데이터 추가**로 처리된다.

| 순서 | 항목 | 예상 |
|---|---|---|
| 1 | 무기 +3~5종, 적 +3종, 유물 +12종 | 데이터 작업 위주 |
| 2 | 스테이지 2 + 보스 2 | 방 풀·보스 데이터 교체 |
| 3 | 런 중간 저장 (이어하기) | `RunState` JSON 덤프 + 복원 — 슬롯 1개, delete-on-load |
| 4 | 키 설정 화면 (리바인딩) | `SaveBindingOverridesAsJson` + UI — 2~3h |
| 5 | 메타 성장 (세이브/로드 포함) | `RunResult` 재활용 |
| — | 언어 추가 (3개국어 이상) | String Table 열 추가 — 코드 수정 없음 |
| 6 | 상점 / 휴식 / 이벤트방 | 방 타입 핸들러 추가 |
| 7 | 무기 등급제 · 강화 | `rarity` 필드 활성화 |
| 8 | AI 판단 층을 BT로 전환 (조건부) | `IPatternSelector` 교체 — GDD 9.1의 도입 신호 확인 후 |
