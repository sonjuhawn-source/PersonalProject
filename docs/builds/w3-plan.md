## 언제 누르는가 — 두 번

| 시점 | 왜 |
|---|---|
| **방 전환이 처음 도는 날** | 참조 그래프와 씬 등록이 여기서 처음 시험된다. 늦게 만나면 원인이 섞인다 |
| **W3 종료** | 회귀 확인 + 정산 |

---

## 이번 주에 새로 생기는 위험

### 1. 참조 그래프 — 가장 큼

W2 에서 활 하나로 겪은 것을 **방 6~8개 + 적 3종**으로 겪는다.

> 에디터에서 손으로 끌어다 놓을 수 있는 것과 빌드에 포함되는 것은 다르다.

방 풀·적 목록을 **배열이나 SO 로 들지 않으면** 에디터에서는 되고 빌드에는 없다.
W2 결과에서 "W4 보상 시스템에서 정면으로 만난다"고 적었는데, **방 풀이 먼저다.**

### 2. 씬을 여러 개로 나눈다면 Build Settings 등록

방 전환을 씬 전환으로 구현하면 등록 안 된 씬은 **빌드에서만 로드에 실패**한다.
프리팹 방식이면 해당 없음 — **어느 쪽으로 갈지 정하는 것이 이 항목의 선결이다.**

### 3. 타일셋 임포트 설정이 빌드에서 다를 수 있다

[#44](../../issues/44) 로 새 에셋이 들어온다. PPU 32 · Point 필터가 플랫폼 오버라이드에
가려지지 않는지 본다. LFS 로 받은 파일이라 **포인터만 받아진 상태면 빌드에서 깨진다.**

### 4. 스테이지 진행 상태가 방 전환을 넘어 살아남는가

씬 전환이면 `DontDestroyOnLoad` 나 데이터 분리가 필요하다. 에디터 Play 에서는 한 씬만
돌려보다 놓치기 쉽다.

## 빌드 전 에디터에서 거를 것

- [ ] 방 풀·적 목록이 배열/SO 참조로 잡혀 있다 (씬에서 손으로 끼운 것만 있지 않다)
- [ ] 씬을 쓴다면 Build Settings 에 전부 등록돼 있다
- [ ] 타일셋 PPU 32 · Point · 압축 설정
- [ ] 방을 끝까지 돌아 스테이지가 끝난다
