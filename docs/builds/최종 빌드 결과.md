# 최종 빌드 결과 — v1.0 (제출물)

> 2026-09-03 · Windows x64 · 상세: [빌드 노트](최종%20빌드%20노트.md) · [로드맵](../roadmap.md)

## 결과

**통과.** 세 번 돌려 빌드에서만 드러난 문제 셋을 잡았고, 마지막 빌드는 문제 없이 완주했다.

| | |
|---|---|
| 빌드 전 정적 확인 8개 | 통과 |
| 실행 · 완주 | 통과 |
| 빌드에서만 드러난 문제 | **3건 — 전부 수정** |

빌드에서만 나온 셋은 [빌드 노트](최종%20빌드%20노트.md)에 근거와 함께 있다 —
첫 프레임 글자 깜빡임, 영어가 안내 문단 상자를 넘음, 같은 방이 반복됨.

**이번 플레이 결과는 성격이 다르다.** *안 되는 것*이 아니라 **콘텐츠 양이 얇다**는
지적이 넷이고, 버그가 하나다.

## 플레이 결과

### 1. 밸런스가 지루하다

기능은 의도대로 돈다. 문제는 **런 전체가 같은 난이도**라는 것이다.

```
적 체력 26      런 내내 고정
적 공격력 3~5    런 내내 고정
검·창 3타       1층부터 보스 앞까지 같다
```

원래 [#135](../../issues/135) 가 **층당 배수** 이슈였는데, 착수하고 보니 곱할 1층 기준이
근거 없이 놓여 있어 범위를 기준 쪽으로 바꿨다. **바닥은 섰고 그 위에 아무것도 안 얹혔다.**

강화가 유일한 변화인데 방향이 반대다 — 플레이어만 세지고 적은 그대로라, 뒤로 갈수록
**쉬워지면서 길어진다.** 41마리를 같은 방식으로 잡는 시간이 지루함의 실체다.

> 진입점은 확인해뒀다. `Health` 와 `EnemyBrain.BuildDamageInfo` 각각 한 군데씩만 곱하면
> 된다 — GDD 12장 미결정.

### 2. 보스가 하나라 단조롭다

오우거 1종 · 패턴 3개 · 페이즈 1이다. 열 칸을 돌아 만나는 유일한 보스라 두 번째 런부터
새로울 것이 없다.

[#115](../../issues/115)(보스 다종화)를 **계획에서 의도적으로 뺐다.** 보스 하나에
프리팹·애니메이터·패턴 SO 셋이 붙고 `#105` 에서 그것이 하루였다. 나흘 안에 확실히 들어갈
크기가 아니었다.

### 3. 무기가 3종뿐이다

검·창·활에 슬롯이 2개다. 이것이 보상방까지 갉아먹는다 — `PickUnheldWeapon` 풀에 늘
**1종만** 남아서 무기 카드가 A↔B 왕복이 되고, 활은 시작 무기에서 빠져 **한 번도 안 쓰고
런이 끝날 수 있다.**

**후속의 첫 카드다.** 무기 SO 래퍼(확장 지점 1번)를 지켰으므로 `WeaponData` 에셋 하나와
오버라이드 컨트롤러로 끝난다 — 코드는 안 건드린다.

### 4. 적 종류가 단순하다

돌진형 · 원거리형 둘이다. `#96` 에서 외형을 갈라 **판단할 시점에 정보가 생겼지만**,
갈릴 행동이 두 가지뿐이라 곧 학습된다.

여기도 확장 지점을 지켜뒀다 — `#74` 에서 원거리형을 만들 때 **`.cs` 를 하나도 안 만들었다.**
`AttackPattern` SO 와 프리팹 변종만으로 갈렸고, `maxHeightDiff` · `keepDistance` ·
`minRange` 조합이 이미 성격을 표현한다.

### 5. 공중 공격 후 착지하면 움직이며 때릴 수 있다 — 버그인데 쓸모가 있다

원인이 한 줄이다.

```csharp
public override bool AllowsHorizontalControl => !startedGrounded;   // AttackState.cs:14
private bool startedGrounded;                                        // Enter 에서 한 번만 정한다
```

`startedGrounded` 는 `Enter` 에서 정해지고 갱신되지 않는다. 공중에서 공격을 시작하면
`false` 로 굳고, **착지한 뒤에도 `AllowsHorizontalControl` 이 계속 `true`** 라 지상에서
이동하며 공격이 이어진다.

의도는 *"공중 공격은 관성을 유지한다"* 였다 — 공중에서 조작을 막으면 공격하는 순간 낙하가
뻣뻣해진다. 그 판단은 맞고, **상태가 시작 시점의 조건을 계속 들고 있는 것**이 새는 자리다.
학습 로그 6절의 *"전환 후에도 이전 상태가 계속 판단했다"* 와 같은 형태다.

**고치지 않았다.** 점프 공격 → 착지 → 이동 공격이 연결되면서 조작 폭이 넓어지는데, 이쪽이
지상 공격이 제자리에 묶이는 지금 구조보다 재미있다. **다만 의도한 것이 아니므로 후속에서
정식 규칙으로 다시 만들 자리다** — 지금은 착지 판정이 없어서 얼마나 오래 이어지는지가
콤보 길이에 달려 있다.

## 이번 빌드에서 배운 것

**"동작하는가"에서 "알 수 있는가"로, 다시 "충분한가"로 옮겨왔다.**

v0.4 결과가 처음으로 *"기능이 도는 것과 읽히는 것은 다르다"* 를 적었다. 이번 결과는 넷이
**양** 얘기다 — 밸런스 곡선, 보스 수, 무기 수, 적 수. 읽히지 않는 문제는 `#96`·`#102`·
`#112` 로 해결됐고, 남은 것은 **콘텐츠 깊이**다.

이것이 1인 6주 범위에서 예상한 결말이다. 그래서 [GDD 9장](../GDD.md)의 확장 지점 넷을
1차에서 지켰다 — 무기 SO 래퍼 · 적·보스 공용 상태머신 · 방 타입 핸들러 · 이벤트 훅 유물.
**넷 중 셋이 이번 지적(무기 · 적 · 보스)에 그대로 대응한다.** 후속이 재작성이 아니라
데이터 작성이 되는지가 다음 빌드에서 증명될 것이다.

**5번은 다른 종류의 교훈이다.** 버그가 재미있을 수 있고, 그때 남길 것은 *"쓸모 있으니
둔다"* 가 아니라 **왜 그렇게 되는지와 정식화하려면 무엇이 필요한지**다. 안 적어두면 다음에
누군가(나 포함)가 "버그니까" 고쳐서 조작 폭이 조용히 줄어든다.
