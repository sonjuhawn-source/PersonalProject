# 최종 빌드 노트 — v1.0 (제출물)

> 작성 2026-09-03 (빌드 직전) · 관련: [W4 다음 빌드 계획](4주차%20다음%20빌드%20계획.md) · [로드맵](../roadmap.md)

**제출물이다.** 마감 2026-09-04(금).

v0.4 에서 런이 처음부터 끝까지 돌아갔으므로, 이번에 들어간 것은 **"동작하는가"가 아니라
"남에게 넘길 수 있는가"** 쪽이다 — 시작 화면 · 소리 · 설정 · 밸런스.

W4 빌드 이후 **이슈 11개**가 들어갔고, 그중 `#135`(밸런스)와 `#137`(소리)이 **모든 교전에
영향**을 준다.

## 조작

시작 화면의 **조작** 버튼에 같은 내용이 있다 ([#120](../../issues/120)).

| 동작 | 키보드 | 게임패드 |
|---|---|---|
| 이동 | **← →** (화살표) | 좌스틱 · D패드 |
| 점프 | **Space** | A (남쪽 버튼) |
| 공격 | **F** | X (서쪽 버튼) |
| 무기 스왑 | **A** | RB |
| 설정 (일시정지) | **ESC** | — (없음) |
| 보상 선택 | **1 · 2 · 3** 또는 클릭 | — |
| 재시작 | **R** 또는 버튼 | — |

**재시작은 런이 끝난 뒤에만 먹는다.** 전투 중에 눌러도 아무 일이 없다.

### 눌러도 아무 일이 없는 키

바인딩만 있고 구현이 없다. 눌러보고 "고장났나" 하지 않도록 적어둔다.

```
D · S     Skill1 · Skill2    #51 · #52 가 1차 범위 밖으로 확정되면서 소멸
E         Interact           쓰는 곳이 없다
```

`Esc`(`Pause`) 는 v0.4 에서 이 목록에 있었는데 [#138](../../issues/138) 에서 살아났다. 다만
`.inputactions` 를 안 거치고 `Keyboard.current` 를 폴링하므로 **게임패드로는 못 연다.**

## 이 빌드의 수치

### 무기 3종

콤보 한 사이클 전체 기준이다. 강화 0 레벨.

| | 사이클 | 총 데미지 | DPS | 리치 |
|---|---|---|---|---|
| 검 | 1.31s (3타) | 35 | **26.7** | 1.10 |
| 창 | 1.64s (3타) | 42 | **25.6** | 1.25 |
| 활 | 0.49s (1타) | 8 | **16.3** | **6** (투사체) |

**창을 [#135](../../issues/135) 에서 낮췄다.** 48 → 42 이고 DPS 가 29.3 → 25.6 이다.
근거는 밸런스가 아니라 **강화 곡선**이었다 — 아래 참조.

시작 무기가 **검 + 창**이다. 둘이 같은 3타라 무기를 바꿔도 첫 방 기준이 안 흔들린다.
활은 보상으로만 들어온다.

스왑 쿨다운은 셋 다 3.3초. 스왑 중에는 대시 + 무적이 붙는다.

### 적 2종

`Enemy.prefab` 공통 — `maxHealth 26` · `moveSpeed 2` · `detectRange 4.5` ·
`staggerTime 0.15` · `deathDelay 0.35`.

| | 패턴 | 사거리 | 데미지 | 쿨다운 | 성격 |
|---|---|---|---|---|---|
| 돌진형 | `Bite` | 0~0.95 | 3 | 0.5 | `maxHeightDiff 0.5` — 같은 층에서만 |
| | `Lunge` | 0.8~1.6 | 5 | 3 | |
| 원거리형 | `Shoot` | 0~4 | 5 | 2 | `maxHeightDiff 100` · `keepDistance 3` |

**역할을 가르는 것은 사거리가 아니라 `maxHeightDiff` 다.** 그리고 원거리형은
[#108](../../issues/108) 에서 `keepDistance` 가 붙어 **붙으면 후퇴한다.**

### 보스 — 오우거

```
maxHealth 250      detectRange 10      패턴 3개 · 페이즈 1
```

| 패턴 | 예고 | 사거리 | 데미지 | 무게 | 쿨다운 |
|---|---|---|---|---|---|
| `OgreSmash` | 0.4 | 0~1.8 | 8 | 3 | 1.2 |
| `OgreCharge` | 0.8 | 1.6~3.5 | 10 | 2 | 4 |
| `OgreThrow` | 0.6 | 3~10 | 6 | 2 | 2.5 |

**셋 다 `interruptible: 0` 이다.** 예고 중에 맞아도 안 끊긴다 — 이게 없으면 붙어서 연타하는
것만으로 보스가 패턴을 한 번도 못 쓴다 ([#105](../../issues/105)).

보스만 [#135](../../issues/135) 의 하향을 안 받았다. `maxHealth` 를 오버라이드하고 패턴도
별도 SO 라 베이스 변경이 안 따라온다.

### 플레이어

`maxHealth 30` · 피격 무적 **0.6초**.

```
Bite 3          10대     초당 5.0
Lunge · Shoot 5  6대     초당 8.3
```

**무적이 초당 피해에 상한을 건다.** 두 마리가 동시에 때려도 한 대만 들어가므로,
적이 많아도 위험이 비례해서 오르지 않는다.

**처치당 체력 1 회복** ([#135](../../issues/135)). 5킬이 한 대를 갚고 최대치에서 멈춘다 —
잘 싸우면 유지되고 맞으면서 싸우면 못 채운다.

### 1층 기준을 타수로 잡았다

| | 1타 | 2타 | 3타 | 4타 | 결과 |
|---|---|---|---|---|---|
| 검 | 10 | 20 | **35** | | 3타 |
| 창 | 12 | 24 | **42** | | 3타 |
| 활 | 8 | 16 | 24 | **32** | 4발 |

적 체력 26이 2타 누적(20 · 24 · 3발 24)보다 크고 3타 누적보다 작다. **셋이 동시에 맞는
값이 여기밖에 없었다.**

창을 낮춘 것이 전제였다. 검 35 대 창 48 이면 *검이 강화로 2타가 되는 조건(HP 28 이하)* 과
*창이 1층부터 2타가 아닐 조건(HP 29 이상)* 이 한 칸 차이로 충돌한다.

### 강화

```
데미지   레벨당 15%      max(원래 + 레벨, round(원래 × (1 + 레벨×0.15)))
공속     레벨당 7%       startup · recovery 를 나눈다. activeTime 은 안 건드린다
교체     활성 슬롯 레벨을 그대로 인계
```

보상방이 4개(`rewardEvery 1`)라 **최대 레벨 4**다. 타수가 줄어드는 지점이 런 안에 들어온다.

| | 3타 → 2타 (활은 4→3발) |
|---|---|
| 창 | **레벨 1** (14+14=28) |
| 활 | **레벨 1** (9×3=27) |
| 검 | **레벨 2** (13+13=26) |

### 방

```
roomCount 5      rewardEvery 1      seed -1 (TickCount)
전투 5 + 보상 4 + 보스 1 = 10칸
```

전투방 적 수는 **4 · 8 · 7 · 12 · 10** 이다. 방 순서는 **풀을 섞어 앞에서부터 꺼낸다** —
`roomCount` 와 풀이 둘 다 5라 **한 런에 모든 방이 정확히 한 번씩** 나오고, 런 적 수가
**41마리로 고정**된다.

**적 수는 난이도가 아니라 길이다.** `detectRange 4.5` 가 화면 반폭(`2.5 × aspect ≈ 4.44`)과
같아 화면에 들어온 적만 깨어나므로 한두 마리씩 온다. 4·5방이 등장은 40%인데 적의 54% 를
가지므로 — **12마리 방은 어려운 게 아니라 세 배 길다.** 셔플이 그 편차를 런 단위로 없앴다.

### 소리

| 자리 | 클립 |
|---|---|
| 검 · 창 공격 | `SwordAttackv1` + 변주 2 |
| 활 발사 | `SmallShotv1` + 변주 2 |
| 플레이어 피격 | `Hurtv1` + 변주 2 |
| 적 피격 | `GetHitv1` + 변주 2 |
| 플레이어 사망 | `SlideDownv1` |
| 적 사망 | `EnemyDiev1` + 변주 3 |
| 스왑 대시 | `SlideUpv8` |
| 보상 선택 | `PowerUpv3` |
| BGM | 시작 `Mysterious Shop` 0.7 · 전투 `Central City Night` 0.4 |

**BGM 이 톤에 안 맞는다 — 알고 쓴다.** 캐주얼 마을 음악이라 액션 배경으로는 어긋나는데,
마감 이틀 전에 액션 트랙을 다시 찾는 것이 견적을 넘었다. 근거는 [GDD 10.3](../GDD.md) 에 있다.
전투 볼륨을 0.4 로 깔아 배경으로만 둔다.

```
해상도     1920 × 1080 · 1600 × 900        빌드에서만 동작한다
화면 모드   창 모드 · 전체 화면              FullScreenWindow
볼륨       전체 · 배경음 · 효과음            AudioMixer · dB 변환
언어       한국어 · English                시작 화면에서만
저장       PlayerPrefs 5키 + selected-locale
```

**언어는 시작 화면에서만 바꿀 수 있다.** 결과 화면 · 보상 카드 · 무기 슬롯이
`GetLocalizedString()` 으로 한 번 뽑는 구조라 런 중에 로케일이 바뀌면 안 따라온다. 전투 중
설정에서는 언어 항목을 감췄다.

폰트는 **Galmuri11 SDF · 203 글리프 · 1024×1024 · Static** 이다. 로컬라이즈 키 29개가
한/영 모두 채워져 있다.

## 알려진 문제

### 절단된 것 — 의도한 것이다

```
보스 2종 이상          #115    후속. 프리팹·애니메이터·패턴 SO 셋이 하루짜리다
보스 페이즈 2          #106    후속
키 설정 (리바인딩)      GDD 11.4 이연
런 중간 저장(이어하기)   GDD 11.3 이연 — 한 런이 5~10분이라 소비자가 없다
메타 진행 · 유물        GDD 7장 · 9장 이연
접촉 피해              GDD 12.8 — 1차에 안 넣는다
낙하 피해              GDD 12.10 — 체력이 얇아 대가가 아니라 사망이 된다
```

### 임시로 둔 것

```
게임패드로 ESC 를 못 쓴다     Keyboard.current 폴링. Gamepad.current 한 줄로 메울 수 있다
검과 창이 같은 공격음         팩에 휘두르는 소리가 하나뿐이다
보스가 잡몹과 같은 피격·사망음  Enemy.prefab 변종이라 물려받는다
RoomData.difficulty         아무도 안 읽는 죽은 필드
씬 오브젝트 이름 플레이스홀더   Text (TMP) · ScreenLable(오타) 등
```

### 남아 있는 문제

**보상 3택이 2택이 되는 방이 있다.** `Compose()` 는 `CurrentHealth < MaxHealth` 일 때만 회복
카드를 넣는다. 처치당 회복 때문에 풀피로 도착하는 일이 늘어 회복 카드가 빠진다. 풀피에
회복을 주는 게 무의미하니 동작은 맞지만 3택이 기획이다.

**무기 카드가 A↔B 왕복이다.** 무기가 3종이고 슬롯이 2개라 `PickUnheldWeapon` 풀에 늘 1종만
남는다. 보상방이 4개라 네 번 다 무기 카드가 뜨고 내용이 반복된다. **무기를 늘리는 것 말고
답이 없다.**

**활을 한 번도 안 쓰고 런이 끝날 수 있다.** 시작 무기에서 빠졌고 보상에서 안 뽑으면 만나지
못한다.

**층이 올라가도 적이 세지지 않는다.** [#135](../../issues/135) 가 원래 그 이슈였는데 곱할
1층 기준이 없어 범위를 바꿨다. 진입점(`Health` · `EnemyBrain.BuildDamageInfo`)은 확인해뒀고
곱할 곳이 각각 한 군데다 — GDD 12장 미결정.

**결과 화면 문장이 영어에서 상자를 조금 넘는다.** `Result_Body`(1.2배) · `Result_Hint`(1.1배)
다. 안내 문단은 `Auto Size` 로 잡았지만 결과 화면은 배율이 낮아 **상자를 넓히는 쪽**이
맞는데, 글자 크기가 언어마다 달라지면 결과 화면이 어색해져서 손대지 않았다. 한국어로는
문제가 없다.

**`Title_Rules` 의 영어가 가운뎃점으로 끝난다.** `Death restarts the run ·` 뒤가 비었다.
항목을 잇는 기호인데 이어지는 것이 없다.

**결과 화면에서 ESC 를 누르면 패널이 겹친다.** 기능 문제는 없다.

**첫 프레임 글자가 이번에 처음 잡혔다.** `LocalizeStringEvent` 가 비동기라 테이블이 도착하기
전까지 씬에 저장된 글자가 보인다. 에디터에서는 테이블이 이미 메모리에 있어 안 드러나고
**빌드에서만 나온다.** 시작 화면에 `Start`·`Quit`·`Option`·`Help` 가, 전투 진입에
`New Text` 가 스쳤다.

## 빌드하면서 나온 것

빌드에서만 드러나는 것 셋을 잡았다. **에디터에서는 하나도 안 보였다.**

### 첫 프레임에 글자가 스쳤다

시작 화면에 `Start`·`Quit`·`Option`·`Help` 가, 전투 진입에 `New Text` 가 한두 프레임 보였다.

`LocalizeStringEvent` 는 문자열을 비동기로 받는다. 테이블이 도착하기 전까지 TMP 에 **씬에
저장된 글자**가 그대로 보이는데, 에디터는 테이블이 이미 메모리에 있어 안 드러난다.

영어가 나온 이유는 **에디터의 미리보기 로케일이 영어**였기 때문이다. 편집 중에도 미리보기로
텍스트를 쓰고 그 결과가 씬 파일에 남는다. `Option` 은 영어 조작 안내가 `Option` 이던 시절
흔적이다.

보이는 자리의 저장 텍스트를 비웠다. `Project Locale` 도 `en` → `ko` 로 바꿨다 — 에디터
로케일은 `Library/` 에 있어 커밋되지 않으므로 다른 기기에서 영어가 다시 구워질 자리였다.

### 영어가 안내 문단의 상자를 넘었다

최장 줄이 한국어의 1.4~1.9배다 (`Title_Rules` 33→62자, `Title_Controls` 42→60자).
줄바꿈은 이미 켜져 있었으므로 **가로가 아니라 세로로** 넘쳤다.

`Auto Size` 를 켜되 **`Max` 를 현재 `fontSize` 와 같게** 뒀다 (Rules 48 · Controls 60).
기본값 72 로 두면 한국어가 부풀어 디자인이 바뀐다. 한국어는 그대로, 영어만 줄어든다.

**짧은 라벨은 손대지 않았다** — `Restart`·`Main Menu`·`Settings` 는 영어가 오히려 짧다.

### 같은 방이 자꾸 또 나왔다

난수는 문제가 없었다. `System.Random` 을 알고리즘 그대로 재현해 시드 10만 개로 재보니 첫
방과 전체 등장이 20.0% 로 균등하다.

원인은 뽑기 구조였다 — 매번 무작위로 뽑고 직전 방만 피하므로 `A B A C B` 가 정상이 된다.

```
다섯 방이 전부 다름      9.4%
같은 방이 두 번 이상    90.6%
```

**균등한 것과 반복이 없는 것은 다른 문제다.** [#135](../../issues/135) 에서 균등함만 확인하고
넘겼다. 풀을 섞어 앞에서부터 꺼내는 방식으로 바꿨다 — `roomCount` 와 풀이 둘 다 5라
중복이 0이 되고 런 길이의 분산도 사라진다.

4  볼륨 셋 · 언어 전환 (껐다 켜서 유지 확인)
