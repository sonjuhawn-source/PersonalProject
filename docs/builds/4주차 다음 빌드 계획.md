## 새 위험

### 1. 빌드 씬이 2개가 된다 — 제일 크다

[#120](../../issues/120) 이 새 씬을 만들고 **씬 전환이 처음 생긴다.**

```
EditorBuildSettings   시작 씬이 index 0 이어야 한다
static                씬 전환에서 살아남는다 — HitStop · Shake
```

`Shake.instance` 는 `OnDestroy` 에서 `instance == this` 일 때만 비운다. 씬 전환 순서에 따라
**새 `Shake` 의 `Awake` 가 옛 것의 `OnDestroy` 보다 먼저 돌면 `instance` 가 null 로 남는다** —
화면 흔들림이 **에러 없이 조용히 죽는다.**

v0.4 의 재시작(같은 씬 리로드)은 통과했지만 **다른 씬으로 갔다 오는 것은 아직 안 돌았다.**

### 2. String Table 에 문자열이 늘어난다

W2 에서 겪은 것 — **참조 사슬이 없으면 빌드에 안 들어간다.** 새 항목을 추가하면 빌드에서
한 번 확인한다.

결과 화면이 지금 문자열을 **하드코딩**하고 있어(`StageRunner.EndRun`) `#103` 이 옮기면
그때 처음 로케일을 탄다. 영어는 절단됐으므로 **폴백이 한국어로 걸려 있는지** 본다.

### 3. `#102` 의 `internal` 벽

지금까지 UI 는 한 방향이었다 — `Gameplay` 가 쏘고 `UI` 가 듣는다. **보상 선택은 왕복이다.**
`IRoomHandler`·`RewardRoomHandler` 가 `internal` 이라 `Game.UI` 에서 안 보이므로 창구를
`StageRunner`(`public`) 에 내야 한다. 여기서 뚫으면 [#112](../../issues/112) 도 싸진다.

## 빌드 전 에디터에서 거를 것

**v0.4 에서 이 목록으로 왕복이 0 이었다.**

```
□  컴파일 에러 0
□  빌드 씬 목록 — #120 이후 2개 · 시작 씬이 index 0        ← 새 항목
□  Pixem 의 using UnityEditor 셋에 #if UNITY_EDITOR 가드
□  테스트 값 잔류 — roomCount · seed · maxHealth · healAmount
□  씬 저장 (git status 로 확인)
□  UI 배선 — HealthBar · RunResultView · 보상 화면 · 시작 화면
□  bundleVersion 을 0.5 로
```

**테스트 값 잔류가 반복 실수다.** `#102` 검증은 보상방까지 가야 해서 `maxHealth` 를 올릴 일이
확실히 생긴다.
