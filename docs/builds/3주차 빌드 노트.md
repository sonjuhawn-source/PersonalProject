# W3 빌드 노트 — v0.3

> 2026-08-21 · 태그 `w3` · Windows x64
> 관련: [W2 빌드 노트](2주차%20빌드%20노트.md) · [W3 빌드 계획](2주차%20다음%20빌드%20계획.md) · [GDD](../GDD.md) · [개발 로드맵](../roadmap.md) · [학습 로그](../learning-log.md)

W3 중간 시점의 제출용 빌드. **W3 종료 빌드가 아니다** — 적 계열이 끝나고 방·스테이지는
착수 전인 상태다.

[빌드 계획서](2주차%20다음%20빌드%20계획.md)는 "방 전환이 처음 도는 날"과 "W3 종료" 두 번을
잡았는데, **제출 주기가 그보다 앞선다.** 그래서 계획서의 W3 신규 체크리스트 5개 중 방 관련
3개(방 전환 · 방 타입 핸들러 · 타일 위화감)는 이번에 볼 수 없다. 그 셋은 다음 빌드로 넘어간다.

## 조작

| 동작 | 키보드 | 게임패드 | 상태 |
|---|---|---|---|
| 이동 | `←` `→` | 왼쪽 스틱 / D-pad | 동작 |
| 점프 | `Space` | A (남) | 동작 |
| 공격 | `F` | X (서) | 동작 |
| 스왑 | `A` | RB | 동작 |
| 스킬 1 | `D` | Y (북) | **이연** — 후속 ([#51](../../issues/51)) |
| 스킬 2 | `S` | B (동) | **이연** — 후속 |
| 상호작용 | `E` | LB | 미구현 — 방 작업([#69](../../issues/69)~[#71](../../issues/71))과 함께 |
| 일시정지 | `Esc` | Start | 미구현 — W5 |

W2 에서 바뀐 항목이 없다. 이번 주 작업이 전부 적 쪽이라 입력은 그대로다.

**종료는 창 닫기 또는 `Alt+F4`.** 일시정지 UI 가 W5 라 게임 안에 종료 경로가 없다.
W1·W2 와 같이 **창 모드 + 크기 조절 가능**으로 냈다.

## 알려진 한계

**의도적으로 남긴 것**과 **놓친 것**을 구분해 적는다. W2 노트에서 스킬 2개를 *미구현* 이 아니라
*이연* 으로 적은 것과 같은 이유다 — 결정해서 안 넣은 것과 빠뜨린 것은 성질이 다르고,
뭉개면 나중에 이 노트를 읽을 때 *의도한 설계였나* 를 알 수 없다.

- **플레이어가 데미지를 안 받는다** — 씬의 `HurtBox.health` 가 비어 있다.
  `TakeHit` 이 `health?.TakeDamage(...)` 로 널 안전해서 **조용히 아무 일도 안 일어난다.**
  적의 공격·예고·경직은 다 동작하지만 체력이 깎이지 않는다. **놓친 것이다**
- **적이 1마리** — 방 배치가 [#69](../../issues/69) 이후라 씬에 하나만 놓여 있다.
  10초면 볼 것이 없어진다
- 체력 UI 없음 — `Game.UI` 어셈블리에 아직 스크립트가 없어 컴파일 대상이 아니다
- 게임 내 종료·재시작 경로 없음

## 기록

| | |
|---|---|
| 적 수치 | 근접 1종 · 패턴 2개 (물기 / 돌진) |
| 방 수 · 스테이지 길이 | 해당 없음 — 방 작업 착수 전 |

계획서는 빌드 크기를 첫 기준점으로 요구했지만 적지 않는다. 지금 규모에서 크기 추이가
말해주는 것이 없고, 재는 것 자체가 일이 된다. 필요해지는 시점은 에셋이 본격적으로 늘어날
때다.
