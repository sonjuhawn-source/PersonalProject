# W2 빌드 계획 — 무기 교체 시스템

> 작성 2026-08-10 (W2 착수 전) · 관련: [W1 빌드 노트](w1.md) · [로드맵](../roadmap.md) · [GDD](../GDD.md)

W1 에서 배운 것 하나로 이 문서가 생겼다 — **빌드는 마감 작업이 아니라 검증 수단이다.**
W1 은 다 만들고 나서야 눌러봤고, 컴파일이 깨져 있었다. 에디터에서는 증상이 없는 축이었다.

W2 는 그 축의 리스크가 더 크다. **로컬라이즈와 에셋 참조가 처음 들어오기 때문이다.**

---

## 언제 누르는가 — 두 번

W1 처럼 주차 끝에 한 번만 누르면 늦다.

| 시점 | 왜 |
|---|---|
| **[#45](../../issues/45) 직후** | `Content` String Table 이 여기서 처음 생긴다. 로컬라이즈는 **에디터에서 되고 빌드에서 안 되는** 대표적인 축이다 |
| **W2 종료** | 회귀 확인 + 다음 주로 넘어가기 전 정산 |

[#45](../../issues/45) 빌드는 **실행까지 안 가도 된다.** 빌드가 나오고 무기 이름이 화면
아닌 로그에라도 제대로 찍히면 통과다. 10분이면 끝난다.

---

## 빌드에서만 드러나는 것

에디터에서 아무리 돌려도 안 나오는 것들. **이번 주에 새로 생기는 축을 우선순위 순으로 적는다.**

### 1. `Content` String Table 이 빌드에 안 들어갈 수 있다 — 가장 큼

Localization 은 테이블을 **Addressables 로 로딩**한다 ([GDD 9장](../GDD.md)).

에디터 Play 모드에서는 에셋 데이터베이스에서 바로 읽히지만, **빌드에서는 Addressables
콘텐츠에 포함돼야 한다.** 테이블을 만들었는데 그룹에 안 들어가 있으면 **빌드에서만
문자열이 비어 나온다.** 에러도 안 난다.

확인법: 빌드 후 무기 이름이 실제 값으로 나오는지. 비어 있거나 키 문자열(`weapon.sword.name`)
이 그대로 보이면 그거다.

`UI` 테이블은 W0 에서 만들었지만 **아직 비어 있고 쓰는 곳도 없어서 검증된 적이 없다.**
`Content` 가 첫 실사용이다.

### 2. 참조 없는 `ScriptableObject` 는 빌드에 안 들어간다

SO 는 **누가 참조해야 빌드에 포함된다.** [#45](../../issues/45) 에서는 `WeaponHolder` 가
인스펙터로 검 SO 를 직접 물고 있어서 안전하다.

문제는 무기 3종이 되는 [#49](../../issues/49) 부터다. 창·활 SO 를 **어디서도 참조하지
않으면 에디터에서는 인스펙터로 바꿔 끼울 수 있는데 빌드에는 없다.**

W4 보상 시스템이 무기 풀을 만들 때 정면으로 만난다. W2 에서는 **무기 목록 SO 하나에
3종을 담아두는 것**으로 미리 막을 수 있다 — [확장 지점](../GDD.md)의 "무기 목록은
배열/풀로 관리"가 이 이야기다.

### 3. `Resources/` 아래는 전부 빌드에 들어간다

굽힌 캐릭터가 `Modified/Resources/` 에 있다 ([GDD 10.2](../GDD.md)). Pixem 도구가
`Resources.LoadAll` 을 쓰기 때문에 그 아래를 벗어날 수 없다.

**참조 여부와 무관하게 `Resources/` 전체가 빌드에 포함된다.** 1차에서 쓰는 건 검·창·활
3종인데 **단검·지팡이·기본형까지 6종이 다 들어간다.**

지금은 용량이 문제될 규모가 아니다. 다만 **빌드 크기를 W1 과 비교해 기록해두면**, 나중에
뭔가 크게 늘었을 때 원인을 좁힐 수 있다.

### 4. `#if UNITY_EDITOR` 가 되돌아갔을 수 있다

Pixem 스크립트 세 개의 `using` 가드는 **에셋을 다시 임포트하면 사라진다**
([GDD 10.1](../GDD.md)). W2 에서 무기 캐릭터를 다시 구우면 재발 가능성이 있다.

빌드가 `CS0246` 으로 깨지면 이것부터 본다.

### 5. 투사체 수명 누락은 오래 돌려야 드러난다

[#48](../../issues/48). 화면 밖으로 나간 화살이 안 죽으면 **에러 없이 조용히 쌓인다.**
에디터에서 30초 테스트로는 안 보인다.

빌드에서 몇 분 돌려보고 프레임이 떨어지는지 본다.

## 빌드 없이도 확인할 것 (에디터에서 먼저)

빌드 전에 여기서 걸러야 빌드 시간을 안 버린다.

- [ ] 무기 SO 를 바꿔 끼우면 외형·클립·사거리·리듬이 전부 바뀐다
- [ ] `PlayerMovement` 에 `combo` 와 `clipWindup` 이 남아 있지 않다
- [ ] `AttackState` 를 한 줄도 안 고쳤다
- [ ] 스왑이 공격을 끊고, 끊긴 히트박스가 꺼져 있다 (`finally` 검증)
- [ ] 창·활 클립의 루프가 꺼져 있고 `Jump` 키프레임이 재구성돼 있다

## W2 빌드 검증 체크리스트

### W1 회귀 — 새 코드가 옛 동작을 깼는지

[#45](../../issues/45) 가 `PlayerMovement` 의 필드를 들어내므로 **콤보가 가장 위험하다.**

- [ ] 좌우 이동 · 점프 · 코요테 타임 · 점프 버퍼
- [ ] 3타 콤보 + 선입력 + 콤보 타임아웃
- [ ] 히트스탑 · 넉백 · 화면 흔들림
- [ ] 피격 무적 + 깜빡임, 적 둘 사이에서 연속으로 안 갈림
- [ ] 적 추격 → 예고 → 공격 → 경직

**[W1 빌드 노트](w1.md)의 수치표와 체감을 비교한다.** 값이 그대로인데 다르게 느껴지면
어딘가 로직이 바뀐 것이다.

### W2 신규

- [ ] 무기 이름이 로컬라이즈 키가 아니라 실제 문자열로 나온다
- [ ] 스왑으로 무기가 바뀌고 외형과 모션이 같이 바뀐다
- [ ] 스왑 대시가 적 공격을 흘린다 (i-frame)
- [ ] 스왑 쿨타임 중에는 안 바뀐다
- [ ] 검·창·활의 사거리와 리듬이 서로 다르게 느껴진다
- [ ] 화살이 날아가 맞고 사라진다. 발사자를 안 때린다
- [ ] 지상 공격 중 조금 전진한다
- [ ] **스왑 순간 한 프레임 옛 그림이 안 보인다** ([#46](../../issues/46) 확인 항목)

### 절단됐다면

[#51](../../issues/51)·[#52](../../issues/52)(스킬·대기 쿨타임)를 이연했다면 위 목록에서
스킬 항목이 빠진다. **주말 산출물 "무기 2개를 번갈아 쓰며 싸운다"는 그래도 성립해야
한다** — 스왑의 대시와 i-frame 이 회피기 역할을 하기 때문이다.

빌드에서 그 문장이 성립하지 않으면 **절단 판단이 틀린 것**이므로 노트에 남긴다.
