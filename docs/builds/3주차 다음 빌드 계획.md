# W4 빌드 계획 — W3 잔여 마무리 우선

> 작성 2026-08-21 (W3 빌드 직후) · 관련: [W3 결과](3주차%20빌드%20결과.md) · [W3 계획](2주차%20다음%20빌드%20계획.md) · [로드맵](../roadmap.md)

**W3 가 절반 남았다.** 적 계열은 끝났고 방·스테이지는 착수 전이다. 다음 주는 **W3 잔여를
먼저 닫고**, 여유가 생기면 W4 이슈를 만들어 착수한다.

---

## 언제 누르는가

| 시점 | 왜 |
|---|---|
| **방 전환이 처음 도는 날** | 참조 그래프가 여기서 처음 시험된다. 늦게 만나면 원인이 섞인다 |
| **제출** | 고정. 그 시점에 있는 것으로 낸다 |

[W3 계획](2주차%20다음%20빌드%20계획.md)은 두 시점을 잡았는데 **제출이 그보다 앞섰다.** 이번부터
제출을 기본으로 두고 위험이 처음 도는 날에 한 번 더 누른다.

## 우선순위

**1 — W3 잔여** ([#69](../../issues/69) · [#70](../../issues/70) · [#71](../../issues/71) · [#72](../../issues/72))

`#69` 가 나머지 셋의 선행이다.

- [ ] 방이 연달아 전환되고 스테이지가 끝난다
- [ ] 방 타입(전투/보상/보스)이 핸들러로 갈린다
- [ ] 창 크기를 바꿔도 방 경계가 어색하지 않다
- [ ] 타일이 캐릭터 옆에서 어색하지 않다
- [ ] **`HurtBox.health` 배선** — W3 의 유일한 놓침

**2 — 여유 시 W4** ([로드맵 W4](../roadmap.md))

보상 3택 1 · 유물 이벤트 훅 · `RunState`/`RunResult` · 런 시작·사망·재시작.
**이슈부터 만든다.** W3 처럼 착수 후 쪼개면 순서가 흔들린다.

## 새로 생기는 위험

**참조 그래프 — 이번엔 실제로 온다.** W2 는 활 하나, W3 는 적 프리팹 하나로 넘겼지만
방은 6~8개다. 방 풀을 배열/SO 로 들지 않으면 **에디터에서는 되고 빌드에는 없다.**
방을 프리팹으로 정했으므로(`6f37ead`) 씬 등록 문제는 해당 없고, 참조 그래프 하나로 모인다.

**해상도가 처음으로 영향을 준다.** 세 번의 빌드에서 "다른 해상도"는 매번 *확인 안 한 것*
이었다. 화면에 바닥만 있었으니 문제가 될 수 없었다. **방 경계([#72](../../issues/72))가 생기면 바뀐다** —
경계 밖이 보이거나 카메라가 갇힌다. `resizableWindow 1` 이니 창 크기를 바꿔가며 본다.

**재시작이 static 을 남긴다** (W4 착수 시). 씬 리로드는 **빌드에서 도메인 리로드가 없어
static 이 살아남는다.** 에디터는 Play 진입마다 리로드가 돌아 안 드러난다 — `HitStop` 의
`ResetStatics` 를 걷어낸 근거가 그것이었다. 최소한 `Time.timeScale` 은 명시적으로 되돌린다.

## 빌드 전 에디터에서 거를 것

- [ ] 방 풀이 배열/SO 참조로 잡혀 있다
- [ ] 방을 끝까지 돌아 스테이지가 끝난다
- [ ] `HurtBox.health` 가 꽂혀 있다
- [ ] 적이 여럿 배치돼 있다 — W3 빌드는 1마리여서 10초면 볼 것이 없었다
