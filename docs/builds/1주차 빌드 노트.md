# W1 빌드 노트 — v0.1

> 2026-08-10 · 태그 [`w1`](../../../commit/9fad406) · Windows x64
> 관련: [GDD](../GDD.md) · [개발 로드맵](../roadmap.md) · [학습 로그](../learning-log.md)

W1 "전투 코어" 종료 시점의 검증용 빌드. **배포용이 아니다.**
목적은 두 가지였다 — 손맛을 에디터 밖에서 확인하는 것, 그리고 **에디터에서는 안 보이는
빌드 전용 문제를 찾는 것**. 후자에서 실제로 하나 나왔다 (아래 "빌드하면서 나온 것").

---

## 조작

| 동작 | 키보드 | 게임패드 | 상태 |
|---|---|---|---|
| 이동 | `←` `→` | 왼쪽 스틱 / D-pad | 동작 |
| 점프 | `Space` | A (남) | 동작 |
| 공격 | `F` | X (서) | 동작 |
| 스왑 | `A` | RB | **미구현** — W2 |
| 스킬 1 | `D` | Y (북) | **미구현** — W2 |
| 스킬 2 | `S` | B (동) | **미구현** — W2 |
| 상호작용 | `E` | LB | **미구현** — W3 |
| 일시정지 | `Esc` | Start | **미구현** — W5 |

바인딩은 전부 등록돼 있고 동작만 아직 없다. `PlayerInputReader` 가 노출하는 것은
`MoveInput` · `JumpPressed` · `JumpHeld` · `AttackPressed` 넷뿐이다.

**위아래는 안 쓴다.** 이동이 2D 벡터로 잡혀 있지만 가로 성분만 읽는다.

**종료는 창 닫기 또는 `Alt+F4`.** 일시정지 UI 가 W5 라 게임 안에 종료 경로가 없다.
그래서 이번 빌드는 전체화면이 아니라 **창 모드 + 크기 조절 가능**으로 냈다.

## 들어 있는 것

- 좌우 이동 (가속·감속 분리, 공중 가속 별도)
- 가변 높이 점프 + 중력 배수 (상승 중 버튼 뗌 / 하강)
- 코요테 타임 · 점프 버퍼
- 3타 콤보 + 선입력 + 콤보 타임아웃
- 히트박스 / 허트박스 + 중복 히트 방지
- 히트스탑 · 넉백 · 화면 흔들림 · 피격 무적 + 깜빡임
- 더미 적 2마리 — 추격 → 예고 → 공격 → 경직, 체력·피격·사망

레벨은 평지 하나. 아트는 구매 에셋 그대로. 사운드 없음. UI 없음.

## 이 빌드의 수치

나중에 "그때가 나았나"를 판단하려면 값이 남아 있어야 한다.

### 이동 · 점프

| | 값 | | 값 |
|---|---|---|---|
| `maxSpeed` | 5 | `jumpHeight` | 1.4 |
| `groundAccel` | 35 | `fallGravityMult` | 2.5 |
| `groundDecel` | 35 | `lowJumpGravityMult` | 3 |
| `airAccel` | 12 | `maxFallSpeed` | 8 |
| `coyoteTime` | 0.1 | `jumpBufferTime` | 0.15 |

카메라 orthographic size `2.5` · PPU 32 · 캐릭터 약 2유닛.

### 플레이어 콤보

| 타 | `startup` | `active` | `recovery` | 데미지 | 넉백 | 히트스탑 | 흔들림 |
|---|---|---|---|---|---|---|---|
| 1 | 0.12 | 0.08 | 0.2 | 10 | 3 | 0.05 | 0 |
| 2 | 0.1 | 0.08 | 0.18 | 10 | 3 | 0.05 | 0 |
| 3 | 0.15 | 0.1 | 0.3 | 15 | 8 | 0.09 | 0 |

`comboResetTime` 0.5 · `clipWindup` 0.1167

**흔들림이 전부 0 인 것은 의도다.** 흔들림은 피격에만 둔다 ([GDD 12.2](../GDD.md)) —
때릴 때도 흔들리면 "맞았다"의 신호가 흐려진다.

### 적 (더미)

`startup` 0.4 · `active` 0.15 · `recovery` 0.6 · 데미지 5 · 넉백 4 ·
히트스탑 0.05 · 흔들림 0.03 · 체력 30 · `moveSpeed` 2 · `attackRange` 0.9 ·
`deathDelay` 0.35

한 사이클이 **1.15초**다. 무적 0.6초보다 길어서 같은 적에게 연속으로 갈리지 않는다.

### 피드백

`Knockback.knockbackTime` 0.2 · `Shake.duration` 0.12 ·
`Invincibility.duration` 0.6 · `blinkInterval` 0.08

## 알려진 문제

**플레이어가 죽지 않는다.** `Health` 를 안 붙였다. `Die()` 가 `Destroy(gameObject)` 라
붙이면 죽는 순간 사라지는데, 사망·재시작이 W4 라 아직 갈 곳이 없다. 맞으면 넉백과
무적만 걸린다.

**시체가 때린다.** 적이 죽고 `Destroy` 까지 0.35초 동안 히트박스가 활성이면 그대로
맞는다. 사망 처리와 히트박스 해제가 아직 안 묶여 있다.

**적 둘이 겹친다.** 서로 밀어내는 로직이 없어서 같은 x 에 포개진다. 무적 검증에는
오히려 편해서 그대로 뒀다.

**낙하 포즈가 이륙 포즈와 같다.** 에셋에 하강 전용 그림이 없어서 체공 프레임을 붙잡아
쓴다 ([GDD 10.1](../GDD.md)). W6 폴리시 항목.

**공격 중 피격이 공격을 끊지 않는다.** `TakeHit` 이 상태머신을 건드리지 않는다.
피격 경직은 아직 없다.

**체력이 화면에 안 보인다.** UI 가 W5 다. 적 체력은 콘솔 로그로만 확인된다.

## 빌드하면서 나온 것

**빌드가 컴파일에서 깨졌다.** 유료 에셋(Pixem) 스크립트 세 개가 `using UnityEditor;` 를
`#if UNITY_EDITOR` **밖에** 두고 있었다. 클래스 본문은 가드 안인데 `using` 만 나와 있어서,
**에디터에서는 증상이 전혀 없고 플레이어 빌드에서만 `CS0246`** 이 난다.

이 스크립트들은 asmdef 가 없어 `Assembly-CSharp` 로 들어간다. 우리 어셈블리가 아무리 잘
닫혀 있어도 같은 빌드에 들어가는 다른 어셈블리가 깨지면 빌드는 안 나온다.

고치는 데 10분이 들었다. **비용이 아니라 발견 시점이 문제였다** — 로드맵은 빌드를 W6 에
뒀는데, 마감 주에 처음 만났다면 남은 시간이 아니라 버퍼 자체가 사라진다.

절차는 [GDD 10.1](../GDD.md) 에 남겼다. **에셋을 다시 임포트하면 되돌아간다.**

> **주차가 끝날 때마다 빌드를 한 번 누른다.** 깨지면 그 주 안에서 고치고, 안 깨지면
> 10분이 든다.

출력은 `Builds/` 이고 `.gitignore` 로 제외한다.

**Addressables 콘텐츠 빌드가 함께 돈다.** Localization 이 String Table 로딩에 쓰기
때문이고, 우리가 직접 쓰는 건 아니다 ([GDD 9장](../GDD.md)). `Debug Build Layout` 은
꺼둔다 — 빌드가 느려지고 지금 볼 이유가 없다.

빌드는 `Assets/Settings/UniversalRP.asset` 과 `UniversalRenderPipelineGlobalSettings.asset`
에 **셰이더 스트리핑 결과를 기록한다.** 빌드할 때마다 다시 써지므로 `git diff` 에 뜨는 게
정상이다.
