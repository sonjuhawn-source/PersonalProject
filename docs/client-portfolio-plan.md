## 할 일 — 위에서부터

### 1. 링크를 넣는다 · 필수

덱에도 README 에도 **GitHub · 빌드 · 플레이 영상 링크가 없다.** 읽는 사람이 가장 먼저 찾는 것이다.

- GitHub Release 에 제출 빌드(v1.0)를 올린다 — README 와 덱이 같은 링크를 쓴다
- 플레이 영상 1~2분 (런 한 판 + 스왑 · 보상 · 보스)
- 표지나 마지막 장에 URL 과 QR

### 2. 코드를 한두 장 보인다 · 필수

설계가 도식으로만 설명돼 있어 **"직접 짰나"를 확인할 장면이 없다.** 도식 옆에 10~15줄 캡처.

| 슬라이드 | 보일 코드 |
|---|---|
| 8 조작 권한 | `PlayerState` 의 권한 선언과 `SwapState` 가 다섯을 끄는 부분 |
| 10 무기 데이터 | `WeaponData.GetAttack` → `AttackData`(struct) 사본이 나가는 부분 |

### 3. 트러블슈팅 1~2장 · 필수

**문제 → 원인 → 해결** 형식. 소재는 학습 로그에 이미 있다.

**실제로 겪은 것**

| 문제 | 원인 | 해결 | 근거 |
|---|---|---|---|
| 에디터에선 멀쩡한데 빌드만 깨졌다 | 유료 에셋의 `using UnityEditor;` 가 `#if UNITY_EDITOR` 밖에 있었다. 에디터에는 그 어셈블리가 있어 증상이 없다 | 가드로 감싸고, **주차마다 빌드를 한 번 누르기로** 했다 | [학습 로그](learning-log.md#에디터에서-도는-것과-빌드가-되는-것은-다르다) · [빌드는 검증 수단이다](learning-log.md#빌드는-마감-작업이-아니라-검증-수단이다) |
| 벽 앞에서만 점프가 막혔다 | 벽 마찰로 `vy` 가 미세한 양수가 돼 "상승 중"으로 읽혔다 | 착지를 속도로 추론하지 않는다 | [학습 로그](learning-log.md#착지를-속도로-추론하지-않는다) · #77 |
| 점프 입력이 가끔 씹혔다 | `WasPressedThisFrame()` 을 `FixedUpdate` 에서 읽어, 건너뛴 렌더 프레임의 입력이 사라졌다 | `Update` 에서 받아 붙잡고 `FixedUpdate` 에서 소비 — 전역 Update Mode 는 안 바꿨다 | [학습 로그](learning-log.md#update-vs-fixedupdate--입력이-씹혔다) |

**미리 피한 것** — "겪은 것"과 섞지 않는다. 둘은 근거의 무게가 다르다.

| 위험 | 대응 | 근거 |
|---|---|---|
| SO 를 런타임에 고치면 값이 에셋에 남고, 같은 무기끼리 공유된다 | 데이터는 SO, 상태는 래퍼(`WeaponInstance`) — 10장 설계의 출발점 | [학습 로그](learning-log.md#scriptableobject-는-플레이-모드를-넘어-남는다) |
| 빌드에는 도메인 리로드가 없어 `static` 이 재시작을 넘어 살아남는다 | 런 상태를 `RunState` 인스턴스로 모아, 재시작이 새 인스턴스를 만드는 것만으로 초기화 | [TC-RUN-05](qa/test-cases.md) |

### 4. 3장 개요 문구

- "몬스터 2종: 창 몬스터 / 활 몬스터 / 보스" — 2종인데 셋을 나열한다. 실제 구분은 **돌진형 · 원거리형 + 보스**
- "적극 적인" → "적극적인"
- "유니티 클로드 연결" — 설명 없이 두면 "AI 가 짠 거냐"는 질문을 부른다. **코드는 직접 작성하고
  AI 는 리뷰 · 문서만 맡았다**([CLAUDE.md](../CLAUDE.md))를 한 줄로 밝히면 오히려 강점이다

### 5. 13장 자체 평가 — 가장 약한 장

"만족도 6/10" 은 근거가 없고 나머지는 단어 나열이다. [roadmap.md](roadmap.md) 의 **실제 판단
기록**으로 바꾼다.

- 무기 스킬을 이연한 이유 — 필수분만으로 2h 초과, 넣으려면 무기를 검증할 적을 줄여야 했다
- 보스 페이즈 2 를 지키기로 했다가 뒤집은 근거 — 값어치가 패턴 수에 비례한다
- 절단 순서 5개 중 4개를 실제로 발동했다

### 6. 작은 것 둘

- **6장 STEP 목록에 9장(입력 관용 수치)이 없다** — 개요 4개와 상세 6장이 1:1 로 안 맞는다
- **12장 셋째 카드 `maxHeightDiff 100`** — "원거리 · 투척은 높이를 안 본다"는 설명 한 줄이 필요하다

**12장 사거리 설명 수정** ([qa-portfolio-plan.md](qa/qa-portfolio-plan.md) 곁가지). 숫자는 SO 값과

### 12장에서 고쳐야 할 문장 — 코드와 다르다

덱에 *"높이차를 넘으면 후보에서 빠진다"* 로 적혀 있는데 **코드는 그렇게 안 한다.**

```csharp
var picked = selector.Select(DistanceToTarget);        // 여기서 쿨다운을 소모하고
if (HeightToTarget > picked.MaxHeightDiff)             // 여기서 버린다
    return false;
```

**뽑힌 뒤에 버려지고 쿨다운을 대가로 낸다.** 후보에서 빠지는 것이 아니다. 이것이
[#143](https://github.com/sonjuhawn-source/WeaponHero/issues/143) 이고, **고치지 않고 열어 두기로 했다**(2026-10-04) — 밸런스가
바뀌는데 확인할 테스트 회차가 없다.

그러면 **덱 문장을 코드에 맞춰야 한다.** 설계 설명 장에 틀린 설명이 들어가 있는 것이
이 덱에서 가장 나쁜 종류의 오류다. 숫자가 다 맞는 장이라 더 그렇다.

```
지금    높이차를 넘으면 후보에서 빠진다
고칠 것  높이차를 넘으면 그 패턴은 안 나간다 — 선택 뒤에 걸러서, 쿨다운을 쓴 채로 버린다
        (결함으로 잡아 뒀다 · #143)
```

**결함을 숨기지 않는 쪽이 낫다.** 읽는 사람이 코드를 열어 보면 어차피 드러나고,
"알고 있고 왜 안 고쳤는지도 적어 뒀다"가 설명 한 줄보다 강하다.
