**모니터가 2560×1440 이다.** 게임은 1920×1080 을 기본으로 잡았으므로, 전체화면에서 스케일링이

결과라는 점을 결과에 적는다.

## 목적을 이렇게 잡은 이유

제출 이후 코드는 바뀌지 않았다. 그러므로 **새 기능을 검증하는 회차가 아니다.** 두 가지를 본다.

**1. 기록이 있는 항목의 회귀.** 1~9절 71개는 주차별 빌드 결과에서 역추출한 것이라, 확인한
시점이 전부 다르다 (W1 ~ 최종). 한 빌드에서 한 번에 다시 보는 것은 이번이 처음이다.

**2. 한 번도 안 본 항목.** 10절 27개는 코드의 분기에서 뽑은 경계 · 비정상 흐름이고 수행 이력이
없다. 여기서 나오는 것이 이번 회차의 실제 수확이다.

## 테스트 방법

| 방식 | 대상 | 근거 |
|---|---|---|
| 수동 · 빌드 | 대부분 | 에디터에서 안 드러나는 축이 따로 있다 — 이 프로젝트에서 세 번 겪었다 |
| 수동 · 에디터 | 시드 고정 · 체력 조작이 필요한 항목 | 빌드는 `seed -1`(무작위)이고 HP 를 만들 수단이 없다 |
| 자동 · EditMode | 방 순서 · 시드 재현 | 확률과 분포는 한 판으로 판정할 수 없다 |

에디터로 수행한 항목은 **결과에 `에디터` 라고 적는다.** 빌드 결과와 섞으면 "빌드에서만
드러나는 축"을 놓친다.

### 자동이 맡는 범위는 세 영역 21개다

```
자동  21     런 구성   4   TC-ROOM-04 · 05 · 07 · 08
             전투 수치 8   TC-WPN-05 · 06 · 07
             에셋 데이터 9  TC-BLD-03 · TC-ENM-05 · 10
수동  나머지 전부
```

**102개 중 21개다.** 씬 없이 돌릴 수 있는 곳부터 붙였다 ([#141](../../issues/141) ·
[#144](../../issues/144) · [#146](../../issues/146)). 검사하는 것이 둘로 갈린다 —
**계산이 맞는가**(픽스처로 입력을 만든다)와 **에셋 값이 의도대로인가**(`AssetDatabase` 로
실제 에셋을 읽는다).

남은 후보는 이렇다.

| 후보 | 상태 |
|---|---|
| 패턴 선택기 — 가중치 · 사거리 · 쿨다운 | **판단 대기.** 높이 조건이 선택기 밖에 있고 그 전에 쿨다운이 소모된다 ([#143](../../issues/143)). 고칠지에 따라 테스트 문장이 갈린다 |
| 코요테 · 버퍼 · 대시 · 무적 시간 | 미착수. 컴포넌트에 붙은 값이라 초기화 진입점이 필요하다 |
| 프리팹 안의 값 — 적 체력 · 감지 범위 | 미착수. SO 만 보고 있다 |

그래서 이번 회차는 **수동이 주력이고 자동은 보조**다. 회차가 끝난 뒤 자동으로 넘길 항목을
결과에서 다시 고른다 — 손이 많이 간 항목과 판정이 애매했던 항목이 우선 후보다.

## 우선순위

무엇이 깨지는가로 나눈다.

| | 뜻 |
|---|---|
| P0 | 런이 깨지거나 진행이 막힌다 · 데이터가 어긋난다 |
| P1 | 규칙이 어긋나지만 런은 이어진다 |
| P2 | 표시 · 편의 문제 |

결함이 나오면 **중요도(영향도)를 따로 매긴다** — 우선순위는 "언제 고칠까", 중요도는 "얼마나
나쁜가"라 같은 축이 아니다.

## 종료 기준

- [ ] P0 항목을 **전부** 수행했다
- [ ] 수행하지 못한 항목은 **사유를 적었다** — 통과로 적지 않는다
- [ ] Fail 은 전부 이슈로 등록하고 TC 에 이슈 번호를 연결했다
- [ ] 재현율을 확인했다 (실패 항목은 3회 시도)
- [ ] 결과 보고서에 집계와 판단 근거를 남겼다

## 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| **개발자와 테스터가 같은 사람** | 아는 경로만 밟는다. 의도한 조작만 시도하게 된다 | 10절 27개를 감이 아니라 **코드의 분기에서** 뽑았다. "해볼 만한 것"이 아니라 "조건이 있는 자리"가 기준이다 |
| 환경이 1대뿐 | 다른 사양 · 다른 해상도에서의 동작을 모른다 | 범위 밖으로 명시한다 |
| 시드가 빌드에서 무작위 | 같은 런을 다시 만들 수 없다 | 런 시작 로그의 시드를 기록한다. 재현이 필요하면 에디터에서 고정한다 |
| 일부 상태를 만들기 어렵다 | HP 3 · 풀피 진입 같은 조건 | 에디터로 수행하고 환경 칸에 표시한다. **값을 되돌리는 것을 종료 절차에 넣는다** |
| 에디터 테스트 값 잔류 | 다음 빌드가 테스트 값으로 나간다 | `roomCount` · `seed` · `maxHealth` · `healAmount` — 반복 실수 목록에 있는 그 값들이다 (TC-BLD-05) |
| 장시간 · 반복 플레이 피로 | 뒤로 갈수록 판정이 느슨해진다 | 세션 9개로 끊는다. 한 번에 다 돌지 않는다 |

## 범위 밖

```
게임패드          바인딩은 있으나 이번 회차에서 안 본다
다른 PC           환경이 하나뿐이다
다른 해상도 모니터  2560 × 1440 하나
배포 · 설치        단독 실행이라 설치 과정이 없다
네트워크           싱글플레이다
```

다섯 번의 빌드 결과에서 계속 "확인 안 한 것"에 있던 항목들이다. **이번에도 안 하는 것이므로
빠뜨린 것이 아니라 정한 것으로 적는다** — 못 한 것과 안 하기로 한 것은 다르다.
