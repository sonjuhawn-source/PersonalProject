# 결함 리포트 양식

> 1회전에서 Fail 이 나오면 이 형식으로 적는다. 적은 뒤 GitHub 이슈로 올리고,
> [테스트 케이스](test-cases.md) 의 해당 항목에 이슈 번호를 연결한다.

---

## 양식

```
제목        [영역] 한 줄로 증상만. 원인이나 추정을 제목에 넣지 않는다

발견 TC     TC-____
빌드        v1.0 (2026-09-03)
환경        Windows 11 · 2560×1440 · 전체화면 / 빌드 또는 에디터
재현율      3/3 · 2/3 · 1/3

재현 절차
  1.
  2.
  3.

기대 결과
실제 결과

중요도      Critical · Major · Minor · Trivial
우선순위    Urgent · High · Normal · Low
첨부        스크린샷 파일명

원인 추정   (아는 범위에서. 모르면 비워 둔다)
```

## 중요도와 우선순위는 다른 질문이다

| | 묻는 것 | 기준 |
|---|---|---|
| **중요도** | 얼마나 나쁜가 | 진행이 막히는가 · 데이터가 어긋나는가 · 보기만 이상한가 |
| **우선순위** | 언제 고칠까 | 발생 빈도 · 우회 수단의 유무 · 남은 일정 |

둘이 갈리는 경우가 있다. **진행이 막히지만 재현이 어렵고 우회가 쉬우면** 중요도는 Critical
이어도 우선순위는 Normal 일 수 있다. 반대로 **사소하지만 첫 화면에서 모두가 보는 것**은
중요도 Minor 에 우선순위 High 가 된다 — 최종 빌드의 "첫 프레임 글자 깜빡임"이 그랬다.

한 칸으로 합치면 이 구분이 사라진다.

## 제목에 원인을 넣지 않는다

```
✘  스왑 쿨타임 계산이 잘못돼 연타가 먹는다
○  [스왑] 쿨타임 중 A 를 연타하면 대시가 두 번 나간다
```

원인은 아직 추정이고, 틀리면 **제목이 틀린 채로 남는다.** 제목은 본 것만 적고 추정은
`원인 추정` 칸에 둔다. 그래야 나중에 원인이 다른 것으로 밝혀져도 리포트가 유효하다.

## 재현율을 꼭 적는다

같은 절차를 **3회 시도**해서 몇 번 나왔는지 적는다. `1/3` 도 버리지 않는다. 재현이 어려운
것과 없는 것은 다르다 — `#55`(시체가 때린다)는 에디터에서 재현하지 못해 미확정으로 남았다가
W3 빌드에서 **편하게 플레이하는 동안 자연히 지나갔다.**

재현이 안 되면 그 사실 자체를 적는다. *"최초 1회 목격 후 10회 시도에서 재현 안 됨"* 은
정보이고, 안 적으면 다음에 같은 것을 처음 보는 것처럼 만난다.

## 예시 — 실제로 있었던 결함

최종 빌드에서 잡힌 것을 이 양식으로 다시 쓴 것이다.

```
제목        [UI] 언어를 영어로 바꾸면 조작 안내 문단이 상자를 넘는다

발견 TC     TC-UI-07
빌드        v1.0 (2026-09-03)
환경        Windows 11 · 1920×1080 · 전체화면 · 빌드
재현율      3/3

재현 절차
  1. 시작 화면에서 설정을 연다
  2. 언어를 English 로 바꾼다
  3. 설정을 닫고 조작 안내를 연다

기대 결과   안내 문장이 상자 안에 들어간다
실제 결과   문장이 상자 아래로 넘쳐 잘린다

중요도      Major      읽을 수 없으니 조작을 알 수 없다
우선순위    High       제출 빌드의 첫 화면이고 우회 수단이 없다
첨부        english_overflow.png

원인 추정   영어 문장이 한국어보다 1.4~1.9배 길어 줄 수가 늘었다.
            상자 높이가 한국어 기준으로 고정돼 있다.
```

**이 결함은 에디터에서 한 번도 안 나왔다.** 빌드를 영어로 실행해 보고서야 발견했다 —
환경 칸에 `빌드` 라고 적는 이유가 그것이다.
