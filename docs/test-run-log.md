### 발견 1 — 조작 안내에 보상 선택 키가 없다

도움말 화면의 조작표는 다섯 줄이다.

```
← →        이동
Space      점프
F          무기 사용
A          무기 교체 · 대시
ESC        설정
```

오른쪽 설명에 *"보상방에서 셋 중 하나를 고른다"* 가 있지만 **어떤 키인지가 없다.** 실제로는
클릭과 숫자키 `1` · `2` · `3` 이 둘 다 동작한다 (`StageRunner.Update`). 영어 도움말도 같다.

**재시작 `R` 도 조작표에 없다.** 다만 결과 화면에 재시작 버튼이 있어 진행이 막히지는 않는다.

이슈로 등록했다 — 아래 결함 리포트.

### 발견 2 — 효과음 볼륨이 0 으로 시작했다 (결함 아님)

켰더니 효과음이 0 이었다. 레지스트리의 저장값을 확인했다.

```
master   1.0      코드 기본값 1.0
bgm      1.0      코드 기본값 0.8    ← 저장된 값이 기본값과 다르다
sfx      0.0      코드 기본값 1.0    ← 저장된 값
```

**빌드 결함이 아니라 이전 실행에서 저장된 값이다.** 다만 이것이 드러낸 문제가 따로 있다 —
**이 환경은 "처음 설치한 사람"의 상태가 아니다.** `TC-UI-04` · `TC-UI-05` 는 기존 설정이
남은 상태에서만 확인된 것이고, 첫 실행 경로는 한 번도 안 봤다.

`TC-UI-10`(첫 실행 기본값)을 새로 세웠다. 수행하려면 `HKCU\Software\WeaponHero\WeaponHero`
를 내보내 백업한 뒤 지우고 실행한다.

**확인했다 — 통과.** 레지스트리를 비우고 실행하니 효과음 1 · 배경음 0.8 로 떴다. 코드의
기본값(`GameSettings.Load` 의 `GetFloat` 두 번째 인자)과 일치한다. 즉 처음 켜는 사람은
정상적인 소리로 시작하고, **세션 1 에서 본 효과음 0 은 이 환경만의 상태였다.**

같은 형태의 함정이 남아 있는지 생각해 둘 것 — 해상도 · 화면 모드 · 언어도 저장되는
값이라, 기존 설정이 있는 환경과 없는 환경에서 결과가 다를 수 있다.

### 보스가 안 끊기는 것은 의도다

`TC-ENM-03`(피격이 적 행동을 끊는다)에서 **보스만 안 끊겼다.** 이것은 결함이 아니라
설계다 — 보스 패턴 셋이 전부 `interruptible: 0` 이다. 잡몹 기준으로 `TC-ENM-03` 은
통과이고, 동시에 **△ 로 남아 있던 `TC-ENM-09`(보스 패턴 비중단)가 채워졌다.**

기대 결과를 "적"으로 뭉뚱그려 쓴 탓에 수행 중에 판정이 헷갈렸다. **잡몹과 보스가 다른
규칙을 따르는 항목은 TC 를 나눠야 한다.**

### 두 결함은 같은 뿌리에서 나왔다

`#149`(숫자키로 고르면 패널이 안 닫힌다)를 파고드니 `StageRunner` 에 주석이 있었다.

> `#103 이 버튼을 붙이면 Update 의 폴링만 사라지고 이 메서드는 남는다`

**숫자키 폴링은 원래 지울 코드였다.** #103 에서 버튼을 붙이며 지웠어야 했는데 남았고,
그래서 세션 1 의 `#148`(조작 안내에 보상 선택 키가 없다)이 생겼다. 안내를 빠뜨린 게
아니라 **안내할 생각이 없던 조작이 코드에 남아 있었다.**

두 이슈를 따로 열었지만 고칠 때는 한 번에 정해야 한다 — 숫자키를 지울지, 정식 기능으로
올릴지.

### 에디터로 만들려던 상태가 플레이 중에 나왔다

`TC-EDGE-10`(체력이 가득한 채 보상방 진입 → 2택)은 상태를 만들기 어려워 **에디터 항목으로
미뤄둔 것**이었다. 그런데 캡처한 화면에 카드가 둘뿐이고 체력 구슬이 가득 차 있었다.

`Compose()` 는 `HP < Max` 일 때만 회복 카드를 넣으므로, **회복 카드가 없다는 것 자체가
체력이 가득했다는 증거다.** 빌드에서 확인한 것으로 기록한다.

### 실패는 결과 표가 아니라 캡처에서 나왔다

`TC-UI-12`(카드 정렬)는 수행 목록에 없던 항목이다. 스크린샷을 보다가 **카드 둘이 왼쪽에
쏠리고 오른쪽 3분의 1이 빈 것**을 발견했다. 플레이 중에는 눈에 안 들어왔다.

**캡처를 남기는 것이 그 자체로 검증 수단이다.** 화면을 정지시켜 놓고 보면 플레이하면서
지나친 것이 보인다.

### #149 의 중요도가 확정됐다

`TC-EDGE-14`(재선택 불가)가 통과해서, 패널이 남아 있어도 **보상이 두 번 적용되지는
않는다**는 것이 확인됐다 (`resolved` 플래그). [#149](../../issues/149) 는 Major 유지다.

### TC 가 없는 조작을 묻고 있었다

`TC-EDGE-22`(일시정지 중 언어를 바꾸면 즉시 반영되는가)는 **애초에 할 수 없는 조작이다.**
전투 씬 설정에는 언어 항목이 없다 (커밋 `5578ebc`). 바로 옆의 `TC-UI-06` 이 *"전투 씬
설정에는 언어가 안 보인다"* 를 확인하는 항목인데, 두 TC 가 서로 모순된 상태로 목록에
있었다.

**경계 TC 를 코드에서 뽑을 때 생긴 구멍이다.** 설정 화면에 언어 항목이 있는 것만 보고
"정지 중에도 바꿀 수 있다"고 가정했는데, 씬에 따라 항목이 달랐다. 결과를 `N/A`(해당
없음)로 두고 표기에 그 뜻을 추가했다 — **실패도 미확인도 아니고, 물음 자체가 성립하지
않는 경우다.**

### HUD 는 멀쩡한데 설정창만 어긋난다

`TC-EDGE-23` 은 HUD 기준으로 통과다. 그런데 같은 조작에서 **설정창이 위로 치우치고
오른쪽이 화면 밖으로 나간다.** 항목 하나가 두 대상을 보고 있어서 결과가 갈렸고,
설정창 쪽을 `TC-EDGE-28` 로 따로 세웠다.

Canvas Scaler 가 `Match = 1`(세로만 맞춤)이고 설정 프리팹 내부가 중앙 앵커 + 고정
오프셋이다. HUD 가 안 깨지는 것으로 보아 **앵커 구성의 차이**로 보이지만, 시작 화면에서도
같은 증상인지 확인해야 원인이 반으로 줄어든다 (열린 창의 재계산 문제인지, 스케일러
문제인지).
