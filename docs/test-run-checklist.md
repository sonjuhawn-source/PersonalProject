# 수행용 체크리스트 — 1회전

> 대상: [테스트 케이스](test-cases.md) 98개 · 빌드 v1.0
>
> **기능별이 아니라 플레이 동선 순으로 배열했다.** 문서 순서대로 돌면 같은 방을
> 몇 번씩 다시 간다. 한 세션에서 확인할 수 있는 것을 묶어 회차를 줄였다.

---

## 시작 전에 적을 것

```
수행일      2026-__-__
수행자      손주환
빌드        v1.0 (Windows x64)
환경        Windows 11 · 1920×1080 · 전체화면/창
시드        런 시작 시 Player.log 에 찍힌 값을 옮겨 적는다
```

**재현율은 실패한 것만 적는다.** 같은 절차를 3회 시도해 몇 번 나왔는지 (`3/3` · `1/3`).
한 번만 나오고 다시 안 되는 것은 **버리지 말고 `1/3` 으로 적는다** — 재현이 어려운 것과
없는 것은 다르다 (W3 에서 `#55` 가 그렇게 잡혔다).

**결과를 모르겠으면 △ 로 둔다.** 통과로 적지 않는다.

### 빌드에 없는 것 — 에디터로 도는 항목

| | 왜 |
|---|---|
| 시드 고정 | 빌드는 `seed -1`(무작위). 고정하려면 에디터에서 `StageRunner.seed` 를 채운다 |
| 체력 조작이 필요한 항목 | HP 3 · 풀피 진입 같은 상태는 만들기 어렵다 |

에디터로 돈 항목은 **환경 칸에 `에디터` 라고 적는다.** 빌드에서 확인한 것과 섞으면
"빌드에서만 드러나는 축"을 놓친다.

> 에디터 값을 건드렸으면 **되돌린다.** `roomCount` · `seed` · `maxHealth` · `healAmount`
> 가 반복 실수 목록에 있는 그 값들이다 (TC-BLD-05).

## 세션 7 — 시드와 방 순서 · 15분 · 에디터

자동 테스트가 이미 보는 항목이라 **인게임에서는 눈으로만 확인**한다.

```
□ TC-ROOM-04  한 런에 전투방이 겹치지 않는다   ⚙ 자동 테스트 있음
□ TC-ROOM-05  같은 시드로 두 번 → 같은 순서    ⚙ 자동 테스트 있음
```

`StageRunner.seed` 를 고정하고 두 번 돌린다. **끝나면 `-1` 로 되돌린다** (TC-BLD-05).

`TC-ROOM-07`(덱 경계) · `TC-ROOM-08`(시드가 다르면 순서도 다름)은 **인게임 항목이 아니다.**
경계 분기는 확률 1/5 이고 순서 분포는 한 판으로 안 보인다. 자동 테스트가 판정하므로
이 회전에서는 Test Runner 를 한 번 돌리는 것으로 갈음한다.

```
□ Test Runner · EditMode · Run All → 4개 통과 · 테스트 개수가 4인지 눈으로 확인
```

## 빠진 것 — 이번 회전의 범위 밖

```
게임패드          바인딩은 있으나 이번 회전에서 안 본다
다른 PC           환경이 하나뿐이다
다른 해상도 모니터  1920×1080 만
```

다섯 번의 빌드 결과에서 계속 "확인 안 한 것"에 있던 항목들이다. **이번에도 안 하는 것이므로
범위 밖으로 명시한다** — 못 한 것과 안 하기로 한 것은 다르다.

## 끝나고 할 일

2. 실패가 나오면 **버그 리포트 양식**으로 따로 적는다 — 재현 절차 · 기대 · 실제 · 재현율 · 우선순위
3. 결함 통계를 뽑는다 — 세션별 · 원인 유형별
4. TC 엑셀 생성
