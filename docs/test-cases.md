## 이 문서의 출처

**새로 만든 목록이 아니다.** 주차별 [빌드 계획](builds/)의 검증 체크리스트와
[빌드 결과](builds/)에 적힌 확인 항목을 TC 양식으로 옮긴 것이다.

그래서 `결과` 열은 추정이 아니라 **그 빌드에서 실제로 나온 값**이다. 확인하지 못한
항목은 통과로 적지 않고 △ 로 둔다 — [W3 결과](builds/3주차%20빌드%20결과.md)의
*"확인 못 했다와 안 된다를 섞지 않는다"* 가 이 열의 규칙이다.

### 무엇을 인게임 TC 로 두는가

**보이거나 안 보이거나, 막히거나 넘어가는 것만 둔다.** 시간·확률·수치는 플레이로
판정할 수 없으므로 [자동화 대상](#자동화-대상)으로 내린다.

무적 0.3초를 예로 들면, 인게임 TC 는 *"스왑 대시 중 적 공격에 체력이 안 깎인다"*
까지만 묻는다. 0.3초인지 0.6초인지는 코드 테스트가 답할 질문이다.

### 표기

| | |
|---|---|
| ✔ | 통과 |
| ✘ | 실패 — 수정함 |
| ⏸ | 실패 — 이연 (근거는 비고) |
| △ | 확인 못 함 |
| N/A | 해당 없음 — 그런 조작·상태가 존재하지 않는다 |
| ⚙ | **자동 테스트가 판정한다** — 사람이 다시 안 본다 ([자동화된 것](#자동화된-것)) |

`선행 조건` 은 기본이 *"새 런 시작"* 이고, 다른 경우만 적는다.
재현이 필요한 항목은 `StageRunner.seed` 를 고정한다 — 런 시작 시
`런 시작 — 시드 N` 이 콘솔에 찍히므로 같은 런을 다시 만들 수 있다.

이쪽은 **계산이 아니라 에셋에 놓인 값**을 본다. `AssetDatabase` 로 `Data/` 의 실제 에셋을
읽으므로, 밸런스를 만지다 구멍이 생기면 여기서 걸린다. 커버리지는 값이 아니라 **관계**로
검사한다 — "0 에서 시작 · 구간이 이어짐 · 10 까지 닿음". 값을 바꿔도 덮여 있으면 통과한다.

픽스처는 `SoFixture` 가 `SerializedObject` 로 `WeaponData` 에 값을 넣는다. **실제 에셋을
읽지 않는 이유**는 검증 대상이 계산식이라 입력을 정할 수 있어야 해서다 — 에셋 값에 의존하면
밸런스를 만질 때 깨지고, 그때 "계산이 틀렸다"와 "값이 바뀌었다"가 구분되지 않는다.

`강화 1레벨에 최소 1은 오른다`(원본 1)와 `원본이 크면 배율이 이긴다`(원본 100)는 **짝이다.**
하나만 두면 값 확인이고, 둘이 있어야 `Mathf.Max` 가드가 어디서 일하는지가 드러난다.

**넷째는 앞의 셋이 통과해도 셔플을 검증하지 못해서 붙였다.** 셔플을 지워 풀 순서 그대로
나오게 해도 앞의 셋은 전부 통과한다 (학습 로그 5절 "통과하는 테스트와 검증하는 테스트는
다르다").

시드를 0~99 로 도는 것은 표본을 늘리려는 게 아니라 **분기에 닿기 위해서다.** 덱 경계 회피
코드는 새 덱의 첫 방이 직전 방과 같을 때만 실행되고 그 확률이 1/5 다.

## 아직 자동화 안 한 것

플레이로 판정할 수 없어 인게임 TC 에서 뺀 것들이다. 전부 씬 없이 EditMode 에서
돌릴 수 있는 위치에 있다.

| 무엇을 | 어디서 | 왜 인게임에서 못 하나 |
|---|---|---|
| 겹치는 사거리에서 가중치 3:1 | `WeightedPatternSelector` | 확률은 한 판으로 안 보인다 |
| 높이차가 근접 패턴을 끊는다 | `EnemyBrain.TrySelectPattern` | 높이차를 눈으로 못 잰다 |
| 쿨다운 중 패턴 제외 | `WeightedPatternSelector` | 초 단위를 못 잰다 |
| 강화 1레벨에 최소 +1 | `WeaponInstance.GetAttack` | 타수로 역산해야 한다 |
| `GetAttack` 이 원본 SO 를 안 바꾼다 | `WeaponInstance` | 값 복사 여부가 화면에 안 나온다 |
| 코요테 0.1 · 버퍼 0.15 · 대시 0.2 · 무적 0.3 | 각 컴포넌트 | 프레임 단위 시간 |

**여기부터는 SO 픽스처가 먼저다.** `AttackPattern` · `WeaponData` 는 필드가 전부
`[SerializeField] private` 이라 테스트에서 값을 넣을 수 없다. `SerializedObject` 주입이나
실제 에셋 로드 중 하나를 정해야 한다 — 테스트 때문에 `public` 으로 여는 것은 순서가 거꾸로다.

패턴 선택기는 **판단이 하나 더 필요하다.** 높이 조건이 선택기가 아니라
`EnemyBrain.TrySelectPattern` 에 있고, 그 전에 `Select()` 가 쿨다운을 이미 소모한다.
거절된 패턴이 한 번도 안 나가고 쿨다운만 도는 것이 의도인지에 따라 테스트 문장이 갈린다.
