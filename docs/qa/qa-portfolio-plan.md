## 방향

**2026-09-23 에 QA 직군으로 전향하기로 정했다.** 클라이언트와 병행이 아니다.
WeaponHero(1차 완료 · 2026-09-03 제출)를 QA 포트폴리오로 다시 구성한다.

양식 기준은 학원 예시 자료다 — `바탕화면\경일\경일 QA TC포폴 예시\` 에 TC 포폴 예시 PDF,
입사지원서 예시, 배그 TC 엑셀이 있다. **한 기기에만 있다** — 2026-09-25 에 덱을 만든 기기에는
없었으므로 덱의 목차 순서는 예시와 대조하지 못했다. 양식은 아래 산출물에 이미 반영돼 있다.

기존 클라이언트용 발표 14장(`바탕화면\손주환 2차 개인프로젝트 포트폴리오` pptx · pdf)은
유지한다. QA 용은 그것을 복사해 **별도 파일**로 만들었다.

## 남은 것

### 1. 캡처 — **집에서** · 40분

```
boss.png     필수   1회전 파일이 보상 화면 중복이다. 공격 예고 중인 장면이면 #150 까지 보인다
엑셀 캡처     필수   TC 시트 — ID · 확인 항목 · 기대 결과 · 결과 · 이슈 번호가 보이게
combat.png   선택   적 두 종류가 같이 나오게. 지금은 같은 종류 둘뿐이라 5번 설명을 못 보여준다
```

`boss.png` 는 **같은 이름으로 덮어쓰고**, [ui-guide.md](ui-guide.md) 표의 번호대로
`Screenshots/numbered/` 에도 번호본을 만든다. 8장의 "캡처 없음" 문단을 걷어내고 이미지 줄을
넣으면 UI 설명서가 끝난다.

**보스전 한 장이 덱의 두 자리를 채운다.** 공격 예고 순간을 잡으면 원본은 #150 슬라이드에,
번호본은 UI 설명서 슬라이드에 들어간다.

### 2. 발표 덱 마무리 — 1시간

덱 안에 **점선 틀**(도형 이름 `캡처 자리 - …`)이 있다. 사진을 틀에 맞춰 올리고 틀은 지운다.

| 쪽 | 자리 | 넣을 것 |
|---|---|---|
| 8 대표 결함 #150 | 흐름도와 카드 사이 세로 칸 | 보스전 원본에서 **보스만** 잘라서 |
| 13 UI 설명서 | 캡처 세 칸 중 가운데 | 보스전 **번호본** |
| 15 제출용 엑셀 | 본문 전체 | TC 시트 |

그 밖에 남은 것.

- **목차(2쪽) 설명 두 곳** — 01 에서 "구조 이해"를 뺀다. 02 는 실제 순서(업무 원칙 → 역할 →
  업무 흐름)에 맞춘다 (진행 중)
- **문구 다듬기** — 슬라이드 문장은 QA 문서에서 줄여 옮긴 것이라 발표 말투로 고친다
- **7쪽 "착수 98 → 109"** — 계획서의 TC 수와 보고서의 수가 다른 이유를 답할 수 있게 둔다.
  [test-plan.md](test-plan.md) 에 98 · 102 · 109 가 섞여 있으니 같이 정리한다

#### 덱 구성과 정한 것

```
1부   1 표지 · 2 목차
      01  3 게임 소개
      02  4 업무 원칙 · 5 담당 역할 · 6 업무 프로세스
      03  7 결함 7건 · 8 대표 결함 #150
      04  9 회고
2부   10 TC 목차
      05  11 계획서 · 12 위험 요소 · 13 UI 설명서 · 14 TC 구성 · 15 제출용 엑셀 · 16 결과 보고서
      17 감사합니다
```

**차별점 넷(판정 규율 · 결함 리포트 · 자동 테스트 · 재현성)은 목차 앞이 아니라 02 안에
"업무 원칙"으로 뒀다.** 계획은 "앞에 둔다"였지만, 목차에 없는 장이 목차와 01 사이에 끼면
원본 덱의 흐름(목차 다음부터 모든 장이 번호 섹션에 속함)이 깨졌다. 02 의 첫 장이라 여전히
앞쪽이다.

**어셈블리 구조 슬라이드는 뺐다.** 계획에서는 "빌드에 무엇이 들어가는지 안다"로 한 장 남기려
했는데, 카드 내용이 개발 판단 그대로라 QA 덱에서는 주제를 벗어난다. 남기려면 카드를 QA
관점(테스트 범위 · 데이터 검증)으로 다시 써야 했다.

클라이언트용의 조작 권한표 · 입력 수치 · 무기 데이터 · 사거리 네 장도 뺐다 — TC 를 설명할 때
한 줄 근거로만 인용한다.

**덱은 저장소에 없다.** 바탕화면이 OneDrive 폴더라 같은 계정이면 다른 기기에서도 열린다.
만든 스크립트는 세션 임시 폴더에 있었으므로, 이후 수정은 PowerPoint 에서 손으로 한다.

## 지켜야 할 것

**원본은 md 이고 엑셀은 파생물이다.** 내용을 고칠 일이 생기면 `test-cases.md` 를 고치고
엑셀을 다시 뽑는다. 엑셀을 직접 고치기 시작하면 둘이 갈라진다.

엑셀 생성 스크립트는 세션 임시 폴더에 있었으므로 **다른 기기에서는 다시 만들어야 한다.**
구조는 `WeaponHero_TC.xlsx` 자체에 남아 있다.

**테스트 스텝 열은 비어 있다.** 1회전에서 결과만 주고받았다. 기억으로 채우면 재현이 안 되는
절차가 나오므로, 2회전에서 수행하며 적는다.
