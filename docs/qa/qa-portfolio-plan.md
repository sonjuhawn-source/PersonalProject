## 방향

**2026-09-23 에 QA 직군으로 전향하기로 정했다.** 클라이언트와 병행이 아니다.
WeaponHero(1차 완료 · 2026-09-03 제출)를 QA 포트폴리오로 다시 구성한다.

양식 기준은 학원 예시 자료다 — `바탕화면\경일\경일 QA TC포폴 예시\` 에 TC 포폴 예시 PDF,
입사지원서 예시, 배그 TC 엑셀이 있다. **이 PC 에만 있으므로 다른 기기에서는 참고 불가**,
다만 그 양식은 아래 산출물에 이미 반영돼 있다.

기존 클라이언트용 발표 PDF 14장(`바탕화면\손주환 2차 개인프로젝트 포트폴리오.pdf`)은
유지한다. QA 용은 별도로 만든다.

## 남은 것

### 1. UI 설명서 — **여기서부터 시작한다** · 남은 일 1시간

**[ui-guide.md](ui-guide.md) 에 화면 10개의 영역 분할과 설명 문구가 이미 들어 있다.**
남은 것은 이미지 편집뿐이다.

```
1. Screenshots/ 의 이미지를 연다 (그림판이면 충분하다)
2. ui-guide.md 의 표에 적힌 번호대로 영역에 사각형과 숫자를 그린다
3. Screenshots/numbered/ 에 같은 이름으로 저장한다
```

번호와 설명은 이미 맞춰져 있으므로 **표는 손대지 않는다.** 색은 캡처와 대비되는 한 가지로
통일한다.

문서에 **결함이 어느 화면에서 나왔는지**도 붙여 뒀다 — 도움말 #148, 보상 #149·#151,
보스전 #150, 일시정지 #152, 결과 #153. 발표 자료에서 이 표와 결함 목록을 나란히 두면
설명이 짧아진다.

### 2. QA 발표 덱 재구성 — 4~5시간 · 구글 슬라이드

예시 자료의 구성을 따른다.

```
1부   담당 게임 소개 · 담당 역할과 업무 프로세스 · 주요 이슈 · 프로젝트 회고
2부   TC 목차 · 테스트 계획서 · UI 설명서 · TC · 결과 보고서
```

**클라이언트용 14장에서 살릴 것** — 04장의 어셈블리 구조는 "빌드에 무엇이 들어가는지 안다"
로 읽히므로 한 장으로 압축해 남긴다. 나머지 설계 슬라이드(권한표 · 무기 데이터 · 패턴)는
검증 근거로만 인용한다.

**차별점으로 앞에 둘 것** — 자동 테스트 21개, 원인 코드까지 짚는 결함 리포트, "확인 못 함"을
통과와 구분한 규율, 시드 기반 재현.

### 3. 자소서 QA 버전 — 2시간

예시 입사지원서 양식에 맞춘다. 재료는 [test-report.md](test-report.md) 의 "이번 회전에서
드러난 것" 넷이 그대로 쓰인다.

## 지켜야 할 것

**원본은 md 이고 엑셀은 파생물이다.** 내용을 고칠 일이 생기면 `test-cases.md` 를 고치고
엑셀을 다시 뽑는다. 엑셀을 직접 고치기 시작하면 둘이 갈라진다.

엑셀 생성 스크립트는 세션 임시 폴더에 있었으므로 **다른 기기에서는 다시 만들어야 한다.**
구조는 `WeaponHero_TC.xlsx` 자체에 남아 있다.

**테스트 스텝 열은 비어 있다.** 1회전에서 결과만 주고받았다. 기억으로 채우면 재현이 안 되는
절차가 나오므로, 2회전에서 수행하며 적는다.
