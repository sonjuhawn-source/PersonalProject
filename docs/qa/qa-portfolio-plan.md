## 방향

**2026-09-23 에 QA 직군으로 전향하기로 정했다.** 클라이언트와 병행이 아니다.
WeaponHero(1차 완료 · 2026-09-03 제출)를 QA 포트폴리오로 다시 구성한다.

양식은 업계에서 쓰는 TC 포트폴리오 서식을 기준으로 잡았다. TC 열 구성(대/중/소분류 ·
사전 조건 · 테스트 스텝 · 기대 결과 · 결과 · 비고 · BTS 링크 · 중요도 · 우선순위 · 테스트 날짜)과
덱 구성(1부 소개·역할·이슈·회고 / 2부 계획서·UI 설명서·TC·결과 보고서)이 거기서 왔다.
**2026-09-25 에 덱을 만든 기기에는 참고 자료가 없어** 목차 순서는 대조하지 못했다.

기존 클라이언트용 발표 14장(`손주환 2차 개인프로젝트 유니티 클라이언트 포트폴리오.pptx`)은
유지한다. QA 용은 그것을 복사해 **별도 파일**로 만들었다. 둘 다 드라이브에 있다.

2026-09-27 에 **02 안의 순서를 바꿨다.** 원래는 `업무 원칙 → 담당 역할 → 업무 프로세스`

클라이언트용의 조작 권한표 · 입력 수치 · 무기 데이터 · 사거리 네 장도 뺐다 — TC 를 설명할 때

## 지켜야 할 것

**원본은 md 이고 엑셀은 파생물이다.** 내용을 고칠 일이 생기면 `test-cases.md` 를 고치고
엑셀을 다시 뽑는다. 엑셀을 직접 고치기 시작하면 둘이 갈라진다.

엑셀 **생성** 스크립트는 세션 임시 폴더에 있었으므로 **다른 기기에서는 다시 만들어야 한다.**
구조는 `WeaponHero_TC.xlsx` 자체에 남아 있다. 스텝을 옮기는 쪽은 잃지 않도록
[`tools/qa/apply_test_steps.py`](../../tools/qa/apply_test_steps.py) 로 저장소에 넣었다 —
md 를 고치고 다시 돌리면 엑셀이 따라온다.

**테스트 스텝 열에 초안이 들어갔다** (108/109 · N/A 한 칸은 비워 둔다). 1회전에서 결과만 주고받았다. 기억으로 채우면 재현이
안 되는 절차가 나오므로, 2회전에서 수행하며 적는다.

2026-09-28 에 **[스텝](test-steps.md) 109개를 먼저 뽑아 뒀다.** 2회전을 빈 종이에서
시작하지 않게 하려는 것이고, 조작법 · TC 의 선행조건과 기대결과 · UI 설명서 · 테스트 메서드
이름에서 나온 것이라 기억이 아니다. 문서가 답하지 못한 11곳은 `[확인]` 으로 표시해 뒀다.
**2회전은 스텝을 따라가며 틀린 줄만 고치는 회차가 된다.**

참고한 TC 서식은 열이 6개뿐인데 **그중 하나가 테스트 스텝**이고 242항목이 전부 채워져
있었다. 재현 절차를 쓸 수 있는지가 QA 의 핵심 역량이라, 이 칸이 비면 산출물이 절반만
있는 셈이다.
