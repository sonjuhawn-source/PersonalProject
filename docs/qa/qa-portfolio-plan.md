## 남은 것

### 1. 캡처 다시 찍기 — **집에서** · 30분

```
boss.png     필수   1회전 파일이 보상 화면 중복이다. 공격 예고 중인 장면이면 #150 까지 보인다
combat.png   선택   적 두 종류가 같이 나오게. 지금은 같은 종류 둘뿐이라 5번 설명을 못 보여준다
```

**같은 이름으로 덮어쓰고**, [ui-guide.md](ui-guide.md) 표의 번호대로 `Screenshots/numbered/`
에도 번호본을 만든다. 8장의 "캡처 없음" 문단을 걷어내고 이미지 줄을 넣으면 UI 설명서가 끝난다.

UI 설명서에는 **결함이 어느 화면에서 나왔는지**도 붙어 있다 — 도움말 #148, 보상 #149·#151,
보스전 #150, 일시정지 #152, 결과 #153. 발표 자료에서 이 표와 결함 목록을 나란히 두면
설명이 짧아진다.

### 2. QA 발표 덱 재구성 — 4~5시간 · 구글 슬라이드

예시 자료의 구성을 따른다.

```
1부   담당 게임 소개 · 담당 역할과 업무 프로세스 · 주요 이슈 · 프로젝트 회고
2부   TC 목차 · 테스트 계획서 · UI 설명서 · TC · 결과 보고서
```

**클라이언트용 14장에서 살릴 것** — 04장의 어셈블리 구조는 "빌드에 무엇이 들어가는지 안다"
로 읽히므로 한 장으로 압축해 남긴다. 나머지 설계 슬라이드(권한표 · 무기 데이터 · 패턴)는
검증 근거로만 인용한다.

**차별점으로 앞에 둘 것** — 자동 테스트 21개, 원인 코드까지 짚는 결함 리포트, "확인 못 함"을
통과와 구분한 규율, 시드 기반 재현.

## 지켜야 할 것

**원본은 md 이고 엑셀은 파생물이다.** 내용을 고칠 일이 생기면 `test-cases.md` 를 고치고
엑셀을 다시 뽑는다. 엑셀을 직접 고치기 시작하면 둘이 갈라진다.

엑셀 생성 스크립트는 세션 임시 폴더에 있었으므로 **다른 기기에서는 다시 만들어야 한다.**
구조는 `WeaponHero_TC.xlsx` 자체에 남아 있다.

**테스트 스텝 열은 비어 있다.** 1회전에서 결과만 주고받았다. 기억으로 채우면 재현이 안 되는
절차가 나오므로, 2회전에서 수행하며 적는다.
