## 이 문서가 무엇인가

제출용 엑셀의 **`테스트 스텝` 열이 109칸 전부 비어 있다.** 참고한 TC 서식은 열이 6개뿐인데
그중 하나가 스텝이고 **242항목이 전부 채워져 있었다.** 재현 절차를 쓸 수 있는지가 QA 의
핵심 역량이라 이 칸이 비면 산출물이 절반만 있는 셈이 된다.

**1회전에서는 결과만 주고받았다.** 기억으로 채우면 재현이 안 되는 절차가 나오므로
[계획](qa-portfolio-plan.md)에서 *"2회전에서 수행하며 적는다"* 로 정했다. 2026-09-28 에
초안을 먼저 뽑아 두고, **2회전 세션 0~8 을 이 문서대로 밟으면서 틀린 줄을 고쳤다.**

고친 자리는 [2회전 기록](test-run-log-2nd.md)에 세션별로 남아 있다. 큰 것 넷은 이렇다.

| TC | 무엇이 틀렸나 |
|---|---|
| `TC-EDGE-27` | 빌드에 없는 해상도(`1280×720`)를 적어 뒀다 → `1600×900` |
| `TC-EDGE-01` 외 셋 | `[에디터]` 를 요구했지만 빌드로 만들 수 있는 상태였다 |
| `TC-EDGE-20` | 판정을 시드 값으로 했는데 `TickCount` 라 충돌한다 → 줄 개수 |
| `TC-BLD-07` | 인스펙터를 훑게 돼 있었다 → `Player.log` |

| 무엇에서 뽑았나 | 어디 |

문서가 답하지 못한 자리는 `[확인]` 으로 표시해 두고 2회전에서 밟아 정했다.
**지금은 하나도 남지 않았다.**

이 문서가 원본이다. 고치면 **엑셀을 다시 뽑는다** — 엑셀을 직접 고치면 둘이 갈라진다.

```
uv run --python 3.12 --with openpyxl python tools/qa/apply_test_steps.py --pre --no-note
uv run --python 3.12 --with openpyxl python tools/qa/audit_tc_sheet.py
```

### 스텝을 쓸 때의 규칙 셋

**행동만 번호로 적고, 관찰은 마지막 줄에 둔다.** *"점프가 나가는지 본다"* 는 스텝이고
*"점프가 나간다"* 는 기대 결과다. 둘을 섞으면 스텝만 보고 밟을 수 없다.

**상태는 사전 조건으로 올린다.** *"HP 를 3으로 만든다"* 는 스텝이 아니라 사전 조건이다.
스텝에 상태 만들기가 섞이면 절차가 길어지고 진짜 확인 대상이 묻힌다.

**남이 같은 순서를 밟을 수 있는 만큼만 적는다.** 3줄이면 3줄이다. 예시 자료도 대부분
3~4줄이다.

## 1. 이동 · 점프 (MOVE)

공통 사전 조건 — **새 런 시작 · 전투방 1 진입 · 적 처치 전**

#### TC-MOVE-01 · 좌우 이동
```
1. ← 를 2초 누른다
2. → 를 2초 누른다
3. 이동 방향과 스프라이트가 바라보는 쪽을 본다
```

#### TC-MOVE-02 · 가변 높이 점프
```
1. Space 를 아주 짧게 눌러 떼고 점프 높이를 본다
2. 같은 자리에서 Space 를 끝까지 누른 채 점프한다
3. 두 높이를 비교한다
```

#### TC-MOVE-03 · 코요테 타임
```
1. 발판 끝까지 걸어간다
2. 발판을 벗어난 직후(0.1초 안에) Space 를 누른다
3. 점프가 나가는지 본다
```
> 코요테 타임은 `PlayerMovement.coyoteTime` 이 **0.1초**다. 점프 버퍼는 0.15초.

#### TC-MOVE-04 · 점프 버퍼
```
1. 높은 곳에서 아래로 떨어진다
2. 착지하기 직전(공중에서) Space 를 누른다
3. 착지와 함께 점프가 나가는지 본다
```

#### TC-MOVE-05 · 낙하 복귀
```
1. 방 안의 구멍(낙하 지점)을 찾아 그 위에 선다
2. 구멍으로 떨어진다
3. 복귀한 위치가 떨어지기 전 마지막으로 발을 붙였던 지점인지 본다
```

## 2. 전투 · 피격 (CMB)

공통 사전 조건 — **새 런 시작 · 전투방 1 · 적 1마리 이상 생존 · 활성 무기 검**

#### TC-CMB-01 · 3타 콤보와 선입력
```
1. 적 앞에서 F 를 누른다
2. 1타 모션이 끝나기 전에 F 를 다시 누른다
3. 같은 방식으로 3타까지 이어 누른다
4. 세 타가 끊기지 않고 이어지는지 본다
```

#### TC-CMB-02 · 콤보 타임아웃
```
1. F 로 1타를 낸다
2. 아무 입력 없이 2초 기다린다
3. 다시 F 를 누른다
4. 나가는 모션이 2타인지 1타인지 본다
```
> 콤보 타임아웃은 `PlayerMovement.comboResetTime` 이 **0.5초**다. 2초면 충분히 넘는다.

#### TC-CMB-03 · 히트스탑 · 넉백 · 화면 흔들림
```
1. 적에게 F 로 한 대 맞힌다
2. 타격이 닿는 순간 화면을 본다
3. 셋이 동시에 나는지 각각 확인한다 — 동작이 멈추는가 · 적이 밀리는가 · 화면이 흔들리는가
```

#### TC-CMB-04 · 피격 무적과 깜빡임
```
1. 적 공격에 일부러 한 번 맞는다
2. 맞은 직후 적 앞에 그대로 서 있는다
3. 스프라이트가 깜빡이는 동안 HUD 체력이 더 줄어드는지 본다
```

#### TC-CMB-05 · 적 둘 사이 연속 피격
```
1. 적 2마리가 함께 있는 방에서 둘 사이로 들어간다
2. 한쪽 공격에 맞는다
3. 깜빡이는 동안 다른 쪽 공격에 몸을 댄다
4. 두 번째 피해가 들어가는지 본다
```
> **전투방 다섯 곳 모두** 풀에 `Enemy_Charger` 와 `Enemy_Ranged` 가 둘 다 있다. 스폰 수는
> 4 · 8 · 7 · 12 · 10 이므로 **수가 많은 Room_4(12) 나 Room_5(10)** 에서 두 종류가 같이
> 나올 확률이 높다.

#### TC-CMB-06 · 지상 공격 중 전진
```
1. 지상에서 적과 조금 떨어져 선다
2. 발 위치를 기억하고 F 를 누른다
3. 공격이 끝난 뒤 발 위치가 앞으로 옮겨졌는지 본다
```

#### TC-CMB-07 · 적 공격이 체력을 깎는다
```
1. HUD 체력 구슬의 현재 상태를 본다
2. 적 공격에 한 번 맞는다
3. HUD 체력이 줄어드는지 본다
```

#### TC-CMB-08 · 공중 공격 후 착지 — **이연 (⏸)**
```
1. Space 로 점프한다
2. 공중에서 F 로 공격한다
3. 공격 모션이 끝나기 전에 착지한다
4. 착지 직후 ← → 입력으로 이동이 되는지 본다
```
> 이연 항목이라 2회전에서도 **기대 결과가 아니라 현재 동작을 그대로 적는다.**
> 근거는 TC 문서에 있다 — `startedGrounded` 래치를 매 프레임 재해석하는 문제다.

## 3. 무기 스왑 (SWAP)

공통 사전 조건 — **새 런 시작 · 무기 2자루 보유 · 스왑 게이지 가득**

#### TC-SWAP-01 · 외형과 모션이 함께 바뀐다
```
1. 현재 플레이어 외형과 HUD 슬롯 표시를 본다
2. A 로 무기를 바꾼다
3. 외형이 바뀐 뒤 F 로 공격해 모션도 바뀌었는지 본다
```

#### TC-SWAP-02 · 스왑 대시의 무적
```
1. 적 공격 예고가 뜨는 것을 보고 그 앞에 선다
2. 공격이 닿는 타이밍에 A 를 누른다
3. HUD 체력이 줄어드는지 본다
```

#### TC-SWAP-03 · 쿨타임 중 스왑 차단
```
1. A 로 무기를 바꾼다
2. 스왑 게이지가 차기 전에 A 를 다시 누른다
3. 무기가 바뀌는지 · 게이지가 초기화되는지 본다
```

#### TC-SWAP-04 · 스왑 순간의 잔상
```
1. 적 앞에서 A 로 무기를 바꾼다
2. 교체 순간 플레이어를 본다
3. 옛 무기 그림이 번쩍이는 것이 눈에 띄는지 본다
```
> **판정 기준을 2회전에서 바꿨다.** 원래는 *"한 프레임도 안 보인다"* 였는데 60fps 에서 한
> 프레임은 16ms 라 **눈으로는 "없었다"를 확인할 수 없다** — 없음의 증명이다.
>
> 이 항목은 [#46](../../../issues/46) 에서 *"교체 순간 옛 그림이 번쩍인다"* 는 **체감**으로
> 들어왔다. 체감으로 들어온 결함은 체감으로 판정하는 것이 맞고, "한 프레임"은 구현
> 디테일이지 사용자가 겪는 것이 아니다.

#### TC-SWAP-05 · 무기 이름 표시
```
1. HUD 무기 슬롯 두 칸의 글자를 읽는다
2. A 로 바꾼 뒤 다시 읽는다
3. `검` 처럼 읽히는지, `weapon.sword.name` 같은 키가 보이는지 본다
```

#### TC-SWAP-06 · 스왑 중 조작 차단
```
1. A 를 눌러 대시를 시작한다
2. 대시가 끝나기 전에 ← → · Space · F · A 를 차례로 누른다
3. 넷 중 하나라도 반응하는지 본다
```

## 4. 무기 · 투사체 (WPN)

#### TC-WPN-01 · 무기 3종이 다르게 느껴진다

## 5. 적 · 보스 (ENM)

#### TC-ENM-01 · 추격 → 예고 → 공격 → 경직
사전 조건 — **전투방 · 돌진형 적 생존**
```
1. 적의 시야 밖에서 천천히 다가간다
2. 적이 따라오기 시작하는 지점을 본다
3. 예고 색이 뜨고, 공격이 나가고, 공격 뒤 적이 멈추는 것까지 순서대로 본다
```

#### TC-ENM-02 · 예고 색이 빌드에서 읽힌다
사전 조건 — **빌드 실행 · 전투방 · 잡몹 생존**
```
1. 적에게 다가가 공격 예고가 뜨게 한다
2. 예고 순간 적 스프라이트 색을 본다
3. 색이 바뀐 것을 화면에서 알 수 있는지 판정한다
```
> **`TC-ENM-11`(보스) 과 나란히 판정한다.** 잡몹은 분홍으로 밝아지고 보스는 어두워져
> 배경에 묻힌다 — 그 대비가 `#150` 의 증거다. 두 캡처를 같이 찍는다.

#### TC-ENM-03 · 피격이 적 행동을 끊는다
사전 조건 — **전투방 · 적 생존**
```
1. 적에게 다가가 예고가 뜨게 한다
2. 예고 중에 F 로 때린다
3. 예고와 공격이 중단되는지 본다
```

#### TC-ENM-04 · 시체가 안 때린다
사전 조건 — **전투방 · 적 생존**
```
1. 적이 공격 모션을 시작하게 만든다
2. 공격이 닿기 전에 마지막 타로 적을 처치한다
3. 시체가 사라지는 동안 몸을 겹쳐 두고 체력이 줄어드는지 본다
```
> **2회전에서 이 절차로 재현됐다.** 1회전에서는 정조준 대신 플레이 시간을 늘려 자연히
> 지나갔던 항목인데, **공격 직전에 처치하는 것**이 핵심이다 — 모션이 시작된 뒤 판정이 나기
> 전 구간이 재현 창이다.

#### TC-ENM-05 · 거리로 패턴이 갈린다
사전 조건 — **돌진형 적 생존**
```
1. 적에게 몸이 닿을 만큼 붙어 공격을 받는다
2. 어떤 패턴이 나오는지 적는다
3. 화면 반 폭쯤 떨어져 다시 공격을 받는다
```

> 경우는 인스펙터로 안 보인다.**

## 다 채우고 나면

**엑셀 반영은 스크립트로 한다.**

```bash
uv run --python 3.12 --with openpyxl python tools/qa/apply_test_steps.py
```

이 문서를 고치고 다시 돌리면 엑셀의 `테스트 스텝` 열이 따라온다. 엑셀을 손으로 고치기
시작하면 둘이 갈라진다. `--pre` 를 주면 `사전 조건` 열도 같이 덮어쓰고, 스텝이 확정되면
`--no-note` 로 요약 시트의 초안 표시를 뺀다.

엑셀의 나머지 빈 열도 같이 정한다. 반쯤 채운 열은 빈 열보다 나쁘다 — "왜 어떤 건 있고
