### `#150` 은 색을 숫자로 쟀다

예고 색은 *"노랗게 보인다"* 로는 판정이 흔들린다. 빌드 캡처에서 보스 몸통 픽셀을 읽었다.

수정 후   RGB(90, 197, 17)      r·g 그대로 · 파랑만 1/4

에디터에서 쟀던 값과 같다. **`#150` 을 닫을 때 빌드 확인을 2회전으로 미뤘는데 여기서

## 이 회전의 결론 — 2회전이 1회전을 검증했다

고친 것을 보는 회차로 시작했는데, **1회전 판정 셋이 뒤집혔다.**

| TC | 1회전 | 2회전 | 왜 |
|---|---|---|---|
| `TC-EDGE-27` | ✔ | ✔ | **빌드에 없는 해상도**(`1280×720`)를 적어 뒀다. TC 를 `1600×900` 으로 고쳐 다시 봤다 |
| `TC-BLD-08` | ✔ | ✘ | `bundleVersion` 이 `0.4` 인데 문서는 `v1.0` 이었다. 그때도 어긋나 있었다 |
| `TC-EDGE-17` | ✔ | N/A | **선행 조건을 만들 수 없다** |

### 1. 값을 안 보고 통과로 넘긴 자리 둘

항목이 많고 하나하나가 짧은 구간(세션 0 · 1)에서 났다. **훑는 속도가 붙으면 판정도 같이
빨라진다.** *"확인 못 한 것을 통과로 적지 않는다"* 는 규칙은 **확인했다고 착각한 것**을
막지 못한다.

### 2. 만들 수 없는 선행 조건 하나

`TC-EDGE-17`(포탈 위에서 사망)의 선행 조건은 `HP 1 · 적 생존 · 출구 열림` 이었다.

```csharp
private void OnCleared()          // remaining <= 0 일 때만 발화한다
{
    currentRoom.ExitTrigger.SetOpen(true);
}
```

**출구는 방의 적이 전부 죽은 뒤에만 열린다.** 적이 남아 있으면 포탈이 안 열리고, 포탈이
열렸으면 때릴 적이 없다.

앞의 둘과 결이 다르다. 값을 안 본 것이 아니라 **TC 를 쓸 때부터 만들 수 없는 상태를 적어
놓은 것**이라, 수행자가 성실해도 통과로 적히거나 미확인으로 남을 수밖에 없다.
**선행 조건이 실현 가능한지는 수행이 아니라 작성 시점에 봐야 한다.**

### 3. 기대 결과가 좁아서 통과했던 둘

```
TC-UI-03     전   전투 중 ESC 로 멈추고 설정이 열린다
             후   멈추고 설정이 열린다. ESC 로든 닫기 버튼으로든 닫으면 재개된다
                  → 여는 것만 보고 있었다. 닫는 경로가 둘인데 구분이 없었다

TC-EDGE-21   전   이동 · 점프 · 공격 입력이 무시된다
             후   어떤 조작도 게임 상태를 바꾸지 않는다 — 이동·점프·공격·무기 교체
                  → 셋만 적혀 있어 셋만 눌러봤다. A 는 아무도 안 눌렀다
```

**기대 결과에 조작을 열거하면 열거된 것만 확인된다.** 둘을 넓히자 `#165` · `#166` 이 나왔다.
`#149`(경로가 둘인데 하나만 밟았다)와 같은 축이고, 이번에는 **TC 쪽**에서 났다.

### 4. 읽는 화면은 플레이로 검사할 수 없다

```
1회전 세션 4   TC-UI-12    보상 카드 정렬
1회전 세션 6   TC-UI-13    결과 화면 겹침
2회전 세션 6   #167        결과 구분자 가려짐
```

**세 번 다 수행 목록에 없던 항목이고 캡처를 보다가 나왔다.** 플레이 중에는 눈이 다음 조작에
가 있어서 화면 구석을 안 본다. 1회전이 *"정지된 화면을 보는 것이 따로 필요하다"* 로
끝났는데, 그 결론이 2회전에서 그대로 다시 맞았다.
