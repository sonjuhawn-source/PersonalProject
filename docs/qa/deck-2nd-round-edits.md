## 먼저 — 쓸 숫자를 한 곳에 모은다

**덱에 숫자를 적기 전에 여기를 본다.** 여러 쪽에 흩어지면 어긋난다.

```
1회전   TC 109 · Pass 96(자동 9) · Fail 12 · N/A 1 · 미확인 0
        신규 결함 7건

2회전   TC 109 · Pass 102(자동 8) · Fail 4 · 이연 1 · N/A 2 · 미확인 0
        회귀 7건 전부 통과 · 신규 결함 3건 · 1회전 판정 3건이 뒤집힘

지금    찾은 결함 10건 · 수정 6건 · 판단해서 안 고침 2건 · 후속 2건
        자동 테스트 21개 · 테스트 스텝 109개 확정
```

> **`Fail 4` 와 `미수정 2` 를 섞지 않는다.** `Fail 4` 는 2회전 시점의 판정이고, 그 뒤
> `#165` · `#164` 를 고쳐 지금은 2건이다. 둘 다 사실이므로 **어느 시점의 숫자인지를 붙여
> 말한다.**

## 쪽별

### 3쪽 · 게임 소개 — **대상 빌드만**

```
v1.0 (2026-09-03 제출본)  →  v1.0 제출본 · v1.1 수정 반영본 (2회전 대상)
```

한 줄이면 된다. 여기서 길게 쓰면 7쪽과 겹친다.

### 4쪽 · 업무 원칙 네 가지 — **두 개가 완료형이 된다**

| 원칙 | 지금 덱 | 바꿀 것 |
|---|---|---|
| 판정 규율 | *확인 못 한 것을 통과로 적지 않는다 · 미확인 0* | **두 회차 모두 미확인 0** |
| 재현성 | 스텝을 2회전에서 확정한다 (계획) | **스텝 109개 확정 · 초안 표시 없음** |
| 자동 테스트 | 21개 | 그대로 |
| 결함 리포트 | 양식 + 예시 | 그대로 |

**재현성 칸이 가장 크게 바뀐다.** 1회전 때는 *"엑셀 스텝 열이 109칸 전부 비어 있다"* 가
약점이었고, 지금은 **확정된 산출물**이다. 한 줄 덧붙일 가치가 있다.

```
제출물에 남아 있던 유일한 미확정 표시를 뗐다
```

### 5쪽 · 업무 프로세스 — **2회전을 붙인다**

지금은 1회전만 그려져 있다. **회차가 둘이 되면서 흐름이 닫힌다.**

```
계획 → TC 작성 → 1회전 수행 → 결함 리포트 → 수정
                      ↓
                  2회전 수행 ─── 회귀 확인
                               └─ 스텝 확정
                               └─ 1회전 판정 검증   ← 이게 포인트
```

**세 번째 가지가 이 덱의 차별점이다.** 보통 2회전은 "고친 걸 다시 본다"로 끝나는데,
여기서는 **1회전 자체의 오판 셋을 잡았다.**

### 7쪽 · 결함 — **가장 많이 바뀐다**

제목부터 바뀐다. `결함 7건` → **`결함 10건 — 찾고, 고치고, 판단했다`**

```
1회전   7건   #148 #149 #150 #151 #152 #153 #154
2회전   3건   #165 #166 #167
```

처리 현황을 표로 둔다. **"전부 고쳤다"가 아니라는 것이 중요하다.**

| | 건수 | |
|---|---|---|
| 수정 · 확인 | 6 | `#148` `#149` `#150` `#152` `#153` `#154` + `#165` `#164` |
| 판단해서 안 고침 | 2 | `#151` 보상 카드 정렬 · `#167` 결과 구분자 — `Trivial` |
| 후속으로 열어 둠 | 2 | `#166` 일시정지 입력 · `#143` 쿨다운 — **검증할 회차가 없다** |

> 발표에서 물어볼 자리다. **"왜 안 고쳤나"에 답이 있어야 한다** — `#143` 은 고치면
> 밸런스가 바뀌는데 확인할 회차가 없다, `#151`·`#167` 은 동작이 아니라 보기 문제다.

### 8쪽 · 대표 결함 `#150` — **고치기 전/후로 교체**

```
지금    Screenshots/boss_only.png        수정 전 한 장
바꿀 것  Screenshots/telegraph_compare.png  전 / 후 / 잡몹 세 칸
```

**새 이미지에 측정값이 박혀 있다.** 캡션은 이미지 안에 있으니 쪽의 설명은 원인 쪽으로
돌린다.

```
애니메이터가 색을 매 프레임 되돌리고 있었다
같은 컨트롤러의 다른 클립(Hit.anim)이 m_Color 를 건드려서, 예고 상태의
클립이 색을 안 건드려도 애니메이터가 소유권을 갖는다 → LateUpdate 에서 유지

RGB(90, 197, 79)  →  RGB(90, 197, 17)      r·g 그대로, 파랑만 1/4
```

> **"없음의 증명" 문제가 해결됐다.** 1회전 때는 캡처 한 장이 *"이 순간에 색이 없었다"*
> 까지만 말했는데, 지금은 **전·후·대조군 셋이 한 장에** 있다.

### 9쪽 · 회고 — **여기가 제일 세진다**

1회전 회고에 **2회전 결론을 얹는다.** 넷 중 하나를 밀어내더라도 넣을 값어치가 있다.

```
2회전은 고친 것을 보는 회차로 시작했는데, 1회전 자체를 검증하는 회차가 됐다
```

| TC | 1회전 | 2회전 | 왜 |
|---|---|---|---|
| `TC-EDGE-27` | ✔ | ✔ | **빌드에 없는 해상도**(`1280×720`)를 적어 뒀다 |
| `TC-BLD-08` | ✔ | ✘ | `bundleVersion` 이 `0.4` 인데 문서는 `v1.0` 이었다 |
| `TC-EDGE-17` | ✔ | N/A | **만들 수 없는 선행 조건이었다** |

**셋째가 성격이 다르다는 것을 말한다.** 앞의 둘은 값을 안 본 것이고, 이것은 TC 를 쓸
때부터 만들 수 없는 상태를 적은 것이라 **수행자가 성실해도 못 막는다.**

여유가 있으면 한 줄 더.

```
기대 결과에 조작을 열거하면 열거된 것만 확인된다
TC-UI-03 · TC-EDGE-21 을 넓히자 #165 · #166 이 나왔다
```

### 14쪽 · TC 구성 — **결과 열이 둘이 됐다**

```
결과 열 둘 — [결과]는 최신 회차, [1회전 결과]는 이력
같은 줄에서 수정 전후가 보인다. 집계와 그래프는 [결과]를 센다
```

**왜 앞에 끼우지 않았는지**를 한 줄 붙이면 좋다 — 집계 수식 59곳과 조건부 서식이 전부
`H` 열을 보기 때문에, 앞에 넣으면 전부 어긋난다. 이런 게 실무 감각으로 읽힌다.

### 15쪽 · 제출용 엑셀 — **캡처 다시**

```
지금    Screenshots/excel_tc.png     결과 열 하나 · 1회전 Fail 다섯이 보인다
찍을 것  결과 열 둘이 같이 보이는 구간
```

**`TC-UI-03` 근처를 잡으면 좋다** — `1회전 Pass` / `결과 Fail` 이 한 줄에 있고 비고에
*"→ 2회전 뒤 수정·빌드 확인"* 까지 들어간다. **한 줄로 세 단계가 보인다.**

### 16쪽 · 결과 보고서 — **두 회차를 나란히**

| | 1회전 | 2회전 |
|---|---|---|
| Pass | 96 | **102** |
| Fail | 12 | **4** |
| N/A | 1 | 2 |
| **미확인** | **0** | **0** |

**미확인 0 두 줄이 이 표의 결론이다.**

## 클라이언트 덱 — 12쪽 한 곳

설계 설명 장에 **코드와 다른 문장**이 있다.

```
지금    높이차를 넘으면 후보에서 빠진다
바꿀 것  높이차를 넘으면 그 패턴은 안 나간다
        — 선택 뒤에 걸러서, 쿨다운을 쓴 채로 버린다 (결함으로 잡아 뒀다 · #143)
```

**결함을 숨기지 않는 쪽이 낫다.** 읽는 사람이 코드를 열면 어차피 드러나고,
*"알고 있고 왜 안 고쳤는지도 적어 뒀다"* 가 설명 한 줄보다 강하다.

`maxHeightDiff 100` 카드에 *"원거리 · 투척은 높이를 안 본다"* 한 줄 넣는 것도
[client-portfolio-plan.md](../client-portfolio-plan.md) 에 적혀 있던 건이다.

## 순서

**숫자가 틀리면 안 되는 것부터.**

```
1   7쪽 결함 현황          숫자가 가장 많이 바뀐 자리
2   16쪽 결과 보고서 집계
3   15쪽 엑셀 캡처 다시
4   8쪽 전/후 이미지 교체    파일만 바꾸면 된다
5   9쪽 회고                차별점 — 시간이 없으면 여기까지
6   4 · 5 · 14쪽           문장 다듬기
7   클라 덱 12쪽
```

**1~4 가 "틀린 것 고치기"이고 5 부터가 "더 세게 만들기"다.** 시간이 모자라면 4까지만 해도
덱이 현재 상태와 어긋나지는 않는다.
