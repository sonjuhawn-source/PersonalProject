### 발견 1 — bundleVersion 이 1차 완성 이후 안 올라갔다 · [#164](../../../issues/164)

```
ProjectSettings   bundleVersion: 0.4      2026-08-30 이후 그대로
문서              v1.0 (1회전) · v1.1 (2회전)
```

W1~W4 는 빌드마다 `0.1 → 0.4` 로 올렸는데 **1차 완성에서 멈췄다.** 주차 리듬이 끝나면서
올리는 행위도 같이 끝났다 — **빌드를 내는 것과 번호를 올리는 것이 습관으로만 묶여 있었다.**

**1회전이 이것을 통과로 적었다.** 그때도 `0.4` 였고 문서는 이미 `v1.0` 이었다. 수행 기록에
이 항목 언급이 한 줄도 없는 것으로 보아, 세션 0 을 훑으면서 **값을 실제로 보지 않고 넘긴**
것으로 보인다.

> **2회전의 값어치가 여기서 처음 나왔다.** 같은 절차를 다시 밟으니 "고친 것"이 아니라
> **1회전의 판정 자체가 틀린 자리**가 드러났다. 회귀 확인이 수정분만 보는 일이 아니라는
> 증거다.

**이번 회전 중에는 안 고친다.** 고치면 빌드를 다시 만들어야 하고, 그러면 지금 돌고 있는
대상이 바뀐다. 회전이 끝난 뒤 다음 빌드에서 올린다.

### 발견 2 — 첫 실행이 영어로 뜬다 (결함 아님)

레지스트리를 비우고 켰더니 **영어로 시작했다.** 로케일 선택 순서를 보면 설정대로다.

```
1  PlayerPrefLocaleSelector   selected-locale   ← 지웠으므로 건너뜀
2  SystemLocaleSelector        OS 표시 언어      ← 여기서 결정
3  CommandLineLocaleSelector   -language=
4  SpecificLocaleSelector      ko               ← 최종 기본값
```

이 기기의 `CurrentUICulture` 가 `en-US` 다. 시스템 로케일은 `ko-KR` 인데 **표시 언어만
영어**로 설정돼 있어서 2번이 영어를 골랐다.

**동작은 의도대로다.** OS 언어를 따르는 것이 `SystemLocaleSelector` 의 일이고, 한국어 표시
언어를 쓰는 기기에서는 한국어로 뜬다.

> 다만 **테스트 환경이 대표적이지 않다.** 한국어를 보려면 매번 바꿔야 하고, 계획서 위험
> 요소의 *"환경이 하나뿐이다"* 가 여기서도 걸린다.

### 발견 3 — TC 가 없는 해상도를 가리키고 있었다

```

제출 빌드(2026-09-03)부터 그랬다
```

**1회전은 이것을 ✔ 로 적었다.** `TC-BLD-08` 에 이어 **둘째**다. 둘 다 "값을 보지 않고 통과로
넘긴" 자리이고, 세션 0·1 처럼 항목이 많고 하나하나가 짧은 구간에서 났다.

TC 를 `1600×900` 으로 고쳤다. **빌드에 있는 것을 확인해야** TC 가 일을 한다. 고친 뒤
다시 보니 통과다.

1회전 기록에는 값을 그대로 두고 [뒤집힌 판정](test-run-log.md#2회전에서-뒤집힌-판정) 절을

## 세션 2 — 전투 기본 · 2026-10-03

**27항목 수행 · 26 통과 · 1 이연.** 이번 회전에서 가장 긴 구간이다.

이연 하나는 `TC-CMB-08`(공중 공격 후 착지)이고 **예상대로 그대로다.** 기대 결과가
*"착지 후에는 공격 중 이동이 막힌다"* 인데 이동이 된다.

```csharp
AllowsHorizontalControl => !startedGrounded     // 래치는 Enter 에서 한 번만 찍힌다
```

공중에서 공격을 시작하면 `startedGrounded` 가 `false` 로 고정이라 **착지해도 계속 이동이
된다.** 코드와 관측이 일치한다. 1차에서 고치지 않은 근거가 체감이 아니라 범위였고
([test-cases.md](test-cases.md)), 그 판단이 유지된다.

### 1회전에서 미확인이던 것들이 채워졌다

`TC-SWAP-06`(대시 중 조작 차단) · `TC-EDGE-05~08`(스왑 경계) · `TC-EDGE-16`(낙하 반복)은
1회전에 결과가 비어 있던 자리다. 이번에 전부 통과로 채웠다.

### 발견 4 — 눈으로 판정할 수 없는 TC 를 고쳤다

`TC-SWAP-04` 의 기대 결과가 *"교체 순간 옛 무기 그림이 **한 프레임도** 안 보인다"* 였다.
60fps 에서 한 프레임은 16ms 라 **눈으로는 "없었다"를 확인할 수 없다** — 없음의 증명이다.

```
전   교체 순간 옛 무기 그림이 한 프레임도 안 보인다
후   교체 직후 옛 무기 잔상이 눈에 띄지 않는다
```

이 항목은 [#46](../../../issues/46) 에서 *"교체 순간 옛 그림이 번쩍인다"* 는 **체감**으로
들어왔다. **체감으로 들어온 결함은 체감으로 판정하는 것이 맞고**, "한 프레임"은 구현
디테일이지 사용자가 겪는 것이 아니다.

> 1회전은 이것을 ✔ 로 적었다. `TC-BLD-08` · `TC-EDGE-27` 에 이어 **셋째**인데 결이 다르다.
> 앞의 둘은 **값을 안 봤고**, 이것은 **볼 수 없는 것을 보라고 적혀 있었다.** 수행자가 아니라
> TC 쪽 문제다.

### 스텝 두 자리를 확정했다

```
TC-SWAP-04   녹화 → 눈으로 본다            판정 기준을 바꿨으므로
TC-ROOM-06   캡처 비교 → 임포트 설정을 읽는다
```

`TC-ROOM-06` 은 화면에서 재면 **카메라 배율이 섞여 들어가** 타일과 캐릭터를 분리할 수 없다.
스프라이트의 `Pixels Per Unit` 을 직접 읽는 쪽이 확실하고 빠르다.

**남은 `[확인]` 은 둘이다** — `TC-ENM-04`(시체 공격 판정 재현법)와 `TC-BLD-07`(UI 배선 확인법).

## 세션 3 — 적과 방 진행 · 2026-10-03

**18항목 수행 · 전부 통과.** 세션 2 에서 이어 보스방 앞까지 갔다.

### `#150` 의 잡몹 회귀가 여기서 확인됐다

`TC-ENM-02`(예고 색이 읽힌다)가 통과다. **`SetTint` 를 `LateUpdate` 로 옮긴 것이 잡몹을
안 깨뜨렸다**는 뜻이다.

잡몹은 애니메이터가 색을 소유하지 않아 `SetTint(false)` 가 원래 색을 복구해야 하는데,
`LateUpdate` 가 `tinted` 일 때만 쓰도록 한 설계가 그것을 살렸다. 보스 쪽은 세션 5 에서 본다.

### `TC-ENM-04` 의 재현법을 확정했다

1회전에서는 정조준이 안 돼 *"플레이 시간을 늘려 자연히 지나갔다"* 였던 항목이다. 이번에는
초안 절차로 재현됐다.

```
적이 공격 모션을 시작하게 만든다
  → 공격이 닿기 전에 마지막 타로 처치
  → 시체가 사라지는 동안 몸을 겹쳐 둔다
```

**핵심은 "공격 직전에 처치"다.** 모션이 시작된 뒤 판정이 나기 전 구간이 재현 창이고, 그
창을 노리면 확실히 잡힌다. 1회전에 "정조준이 어렵다"고 적었던 것은 **창을 몰랐기 때문**이다.

> `[확인]` 이 하나만 남았다 — `TC-BLD-07` 의 UI 배선 확인법. 세션 8 에서 정한다.


**안 고친 것이 그대로인 것을 확인하는 것도 회귀 확인이다.** 통과로 바뀌었다면 아무도 안

## 세션 5 — 보스와 런 종료 · 2026-10-03

**12항목 수행 · 10 통과 · 2 실패 · 1 해당 없음.** 신규 결함 **둘**이 나왔다.

### `#150` 이 빌드에서 확인됐다 — 이번 회전의 핵심

`TC-ENM-11`(보스 예고 색)이 **통과다.** 캡처를 재서 숫자로 확인했다.

```
원본      RGB(90, 197, 79)
빌드 캡처  RGB(90, 197, 17)      r·g 그대로, 파랑만 1/4
```

에디터에서 쟀던 값과 같다. **애니메이터가 색을 되돌리던 것이 `LateUpdate` 유지로 막혔고,
그것이 빌드에서도 동작한다.** `#150` 을 닫을 때 빌드 확인을 2회전으로 미뤘는데 여기서 밟혔다.

세 패턴(Smash · Charge · Throw)의 예고가 전부 보였고 `TC-ENM-08` · `TC-ENM-09` 도 통과다.

### 발견 5 — 설정 닫기 버튼으로 나가면 게임이 멈춘 채로 남는다 · [#165](../../../issues/165)

`ESC` 로 일시정지하고 **닫기 버튼**을 누르면 패널은 닫히는데 **게임이 멈춘 채로 남는다.**

`PauseMenu` 에 이렇게 적혀 있다.

```csharp
// 설정 패널의 닫기 버튼도 이것을 부르면 상태가 한 곳에서만 바뀐다.
public void Toggle()
```

**"부르면" 이라고 적어 뒀고 안 부른다.** `Settings.prefab` 의 `onClick` 은
`GameObject.SetActive` 를 직접 건다. 그래서 `paused` 가 `true` 로 남고
`Update` 의 `if (paused) Time.timeScale = 0f;` 가 **매 프레임 다시 0 을 주장한다.**

`ESC` 를 한 번 더 누르면 풀리지만, 패널도 안 보이고 멈춰 있으니 **무엇을 눌러야 할지 알 수
없다.**

### 발견 6 — 일시정지 중에 무기 교체가 된다 · [#166](../../../issues/166)

`A` 가 먹힌다. 원인은 **일시정지가 입력을 막지 않는 것**이다.

```
이동 · 점프   FixedUpdate      timeScale 0 이면 안 돈다      "저절로" 막힌다
공격          Update(Tick)     입력은 받지만 진행이 시간 기반이라 안 보인다
스왑          Update           즉시 바뀌고 HUD 에 보인다      ← 유일하게 드러난다
```

**셋 다 입력은 통과하고 있었다.** 이동·점프가 막히는 것은 막으려고 막은 것이 아니라
`FixedUpdate` 가 안 돌기 때문이다.
