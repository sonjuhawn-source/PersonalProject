## 1. 용어 치환 — 전 쪽

피드백의 *"처음 보는 사람 입장에서 모호한 부분이 있음"* 이 가리키는 본체다. 아래 셋이
같은 지적 하나다.

### `EditMode` → **유니티 에디터 테스트**

```
□ 4쪽   업무 원칙 "자동 테스트" 칸
□ 14쪽  TC 구성
□ 16쪽  결과 보고서 집계
□ 그 밖에 EditMode 가 보이는 모든 곳
```

### `뽑다` → **추출하다**

```
□ "엑셀을 뽑는다"      → "엑셀을 추출한다"
□ "스텝을 뽑아 뒀다"    → "스텝을 추출했다"
□ "어디서 뽑았는가"     → "어디서 추출했는가"
```

### `런` — **한 단어로 못 바꾼다. 두 뜻으로 쓰고 있다**

```
게임 용어   "한 런을 완주한다" = 로그라이크 1판
            → 3쪽에서 한 번 정의하고 그대로 쓴다. 이 게임의 구조다

QA 문맥     "런을 돌려 확인"   = 테스트 수행
            → "재현한다" · "수행한다" 로 바꾼다. 피드백이 가리킨 쪽이다
```

**3쪽에 넣을 정의 한 줄.**

```
런 — 입장부터 사망 또는 클리어까지. 방 10개를 지난다
```

### `회전` → **차수** — 피드백에 없던 것, 판단해서 넣는다

`1회전 / 2회전` 은 한국어 QA 표준어가 아니다. **`1차 / 2차`** 또는 **`1회차 / 2회차`** 로
쓴다. 같은 축의 지적인데 목록에 없었을 뿐으로 본다.

```
덱      바꾼다 — 발표는 설명할 기회가 한 번뿐이다
문서    336곳이다. 그대로 둔다 — GitHub 은 읽으며 맥락을 잡는 매체다
```

둘이 달라지는 것이 걸리면 [test-plan.md](test-plan.md) 머리에 한 줄이면 된다 —
*"이 저장소에서 '회전' 은 테스트 수행 1회차를 뜻한다"*.

### 그 밖에 한 번은 풀어 쓸 것

처음 보는 사람 기준으로 **첫 등장에서 한 번만** 풀고 그 뒤로는 줄여 쓴다.

```
TC        테스트 케이스(TC)
회귀      회귀 — 고친 것이 다시 깨지지 않았는지 보는 것
이연      이연 — 이번 범위에서 빼고 뒤로 미룬 것
SO        설정 데이터 에셋(ScriptableObject)
```

## 2. 어투 · 폰트 · 정렬 — 전 쪽

> `폰트 통일` · `포트폴리오 어투 - 음슴체, --했습니다` · `결과 보고서 - 왼쪽 정렬 통일`

**셋 다 "섞여 있다"는 지적이다.** 내용이 아니라 하나로 정하라는 것.

### 어투 — 음슴체를 권한다

```
"7건을 발견했습니다"   →   "결함 7건 발견"
"확인했습니다"         →   "확인함"
```

슬라이드는 짧아야 하고 줄이 하나씩 줄어든다. **`~했습니다` 는 말로 하는 것이지 슬라이드에
적는 것이 아니다.** 다만 **한 덱 안에서 섞지만 않으면 어느 쪽이든 된다.**

> **문서(GitHub)의 `~다` 체는 그대로 둔다.** 매체가 다르고, 지금 톤이 이 저장소의 성격이다.

### 폰트 — 세 종류까지

```
제목        하나
본문        하나
수치 · 코드  고정폭 하나 (D2Coding · Consolas)
```

**수치와 코드를 고정폭으로 몰면 그 자체로 구분이 된다.** 지금 몇 종을 쓰고 있는지 먼저
세어 본다.

### 정렬 — 가운데는 표지와 간지만

```
표지 · 간지   가운데
그 외 전부    왼쪽
```

피드백이 16쪽(결과 보고서)을 짚었지만 **다른 쪽에도 같은 것이 있을 가능성이 높다.**
한 번에 훑는다.

**훑고 나니 지적받은 쪽이 아니라 다른 두 쪽이 문제였다.** 전 문단의 정렬을 세어
보니 가운데가 62곳인데, 그중 대부분은 박스 안에 들어 있는 라벨이라 가운데가 맞다.
남은 것을 걸러 내자 같은 모양의 표 셋이 서로 다르게 정렬돼 있었다.

```
5쪽   업무 프로세스 표      왼쪽
6쪽   담당 역할 표         가운데   ← 어긋남
12쪽  테스트 계획서 표      가운데   ← 어긋남
```

**셋 다 머리글 한 줄에 2열인 같은 표인데 하나만 왼쪽이었다.** 지적받은 16쪽만
고쳤으면 이건 그대로 남았다. 15쪽의 가운데 한 줄은 위아래 카드 묶음을 잇는
자리라 의도된 것으로 보고 두었다 — **통일은 규칙이 같은 것들 사이에서만 뜻이 있다.**

## 3. 2차 내용 반영

### 먼저 — 쓸 숫자를 한 곳에 모은다

**덱에 숫자를 적기 전에 여기를 본다.** 여러 쪽에 흩어지면 어긋난다.

```
1차   TC 109 · Pass 96(자동 9) · Fail 12 · N/A 1 · 미확인 0
      신규 결함 7건

2차   TC 109 · Pass 102(자동 8) · Fail 5 · N/A 2 · 미확인 0
      회귀 7건 전부 통과 · 신규 결함 3건 · 1차 판정 3건이 뒤집힘

지금  찾은 결함 10건 · 수정 6건 · 판단해서 안 고침 2건 · 후속 2건
      유니티 에디터 테스트 21개 · 테스트 스텝 109개 확정
```

> **`Fail` 은 두 차수 모두 이연을 포함한 수다.** 1차 12 에 이연 1(`TC-CMB-08`)이 들어
> 있으므로 2차도 5 로 센다 — 실패 4 + 이연 1. **엑셀 집계 수식이 세는 값과도 같다.**
> 보고서에서 이연을 따로 뽑아 적은 것은 거기에 *"(Fail 에 포함)"* 이라는 단서가 같이
> 있기 때문이고, 덱에는 그 단서를 넣을 자리가 없다.

> **`Fail 4` 와 `미수정 2` 를 섞지 않는다.** `Fail 4` 는 2차 시점의 판정이고, 그 뒤
> `#165` · `#164` 를 고쳐 지금은 2건이다. 둘 다 사실이므로 **어느 시점의 숫자인지를
> 붙여 말한다.**

### 7쪽 · 결함 — 가장 많이 바뀐다

제목부터 바뀐다. `결함 7건` → **`결함 10건 — 찾고, 고치고, 판단함`**

```
1차   7건   #148 #149 #150 #151 #152 #153 #154
2차   3건   #165 #166 #167
```

처리 현황을 표로 둔다. **"전부 고쳤다"가 아니라는 것이 이 쪽의 요점이다.**

| | 건수 | |
|---|---|---|
| 수정 · 확인 | 6 | `#148` `#149` `#150` `#152` `#153` `#154` + `#165` `#164` |
| 판단해서 안 고침 | 2 | `#151` 보상 카드 정렬 · `#167` 결과 구분자 — `Trivial` |
| 후속으로 열어 둠 | 2 | `#166` 일시정지 입력 · `#143` 쿨다운 — **검증할 차수가 없다** |

> 발표에서 물어볼 자리다. **"왜 안 고쳤나"에 답이 있어야 한다** — `#143` 은 고치면
> 밸런스가 바뀌는데 확인할 차수가 없다, `#151`·`#167` 은 동작이 아니라 보기 문제다.

### 16쪽 · 결과 보고서 — 두 차수를 나란히 · 왼쪽 정렬

| | 1차 | 2차 |
|---|---|---|
| Pass | 96 | **102** |
| Fail | 12 | **5** |
| N/A | 1 | 2 |
| **미확인** | **0** | **0** |

**미확인 0 두 줄이 이 표의 결론이다.** `Fail` 은 두 차수 모두 이연을 포함한다.

### 15쪽 · 제출용 엑셀 — **확대 컷 셋**

> 피드백 `tc 엑셀 → 중요한 부분만 몇 개 확대해서`

시트 전체 캡처는 글자가 안 읽힌다. **확대 컷 셋으로 간다.**

```
① TC-UI-03 한 줄     1회전 Pass | 결과 Fail | 비고 "→ 2회전 뒤 수정·빌드 확인"
                     ← 한 줄에 "찾았다 → 고쳤다" 가 다 보인다
② 테스트 스텝 칸      절차가 채워져 있다는 증거. 1차 때 비어 있던 열이다
③ 요약 시트 집계      수식과 그래프
```

### 8쪽 · 대표 결함 `#150` — 이미지 교체

```
지금    Screenshots/boss_only.png          수정 전 한 장
바꿀 것  Screenshots/telegraph_compare.png   전 / 후 / 잡몹 세 칸
```

**새 이미지에 측정값이 박혀 있다.** 캡션은 이미지 안에 있으니 쪽의 설명은 원인 쪽으로
돌린다.

```
애니메이터가 색을 매 프레임 되돌리고 있었음
같은 컨트롤러의 다른 클립(Hit.anim)이 m_Color 를 건드려서, 예고 상태의 클립이
색을 안 건드려도 애니메이터가 소유권을 가짐 → LateUpdate 에서 유지

RGB(90, 197, 79)  →  RGB(90, 197, 17)      r·g 그대로, 파랑만 1/4
```

> **"없음의 증명" 문제가 해소됐다.** 1차 때는 캡처 한 장이 *"이 순간에 색이 없었다"*
> 까지만 말했는데, 지금은 **전·후·대조군 셋이 한 장에** 있다.

### 9쪽 · 회고 — 여기가 제일 세진다

1차 회고에 **2차 결론을 얹는다.** 넷 중 하나를 밀어내더라도 넣을 값어치가 있다.

```
2차는 고친 것을 보는 차수로 시작했는데, 1차 자체를 검증하는 차수가 됨
```

| TC | 1차 | 2차 | 왜 |
|---|---|---|---|
| `TC-EDGE-27` | 통과 | 통과 | **빌드에 없는 해상도**(`1280×720`)를 적어 뒀음 |
| `TC-BLD-08` | 통과 | 실패 | `bundleVersion` 이 `0.4` 인데 문서는 `v1.0` 이었음 |
| `TC-EDGE-17` | 통과 | N/A | **만들 수 없는 선행 조건이었음** |

**셋째가 성격이 다르다는 것을 말한다.** 앞의 둘은 값을 안 본 것이고, 이것은 TC 를 쓸
때부터 만들 수 없는 상태를 적은 것이라 **수행자가 성실해도 못 막는다.**

여유가 있으면 한 줄 더.

```
기대 결과에 조작을 열거하면 열거된 것만 확인됨
TC-UI-03 · TC-EDGE-21 을 넓히자 #165 · #166 이 나옴
```

### 4쪽 · 업무 원칙 — 둘이 완료형이 된다

| 원칙 | 지금 | 바꿀 것 |
|---|---|---|
| 판정 규율 | 확인 못 한 것을 통과로 적지 않음 · 미확인 0 | **두 차수 모두 미확인 0** |
| 재현성 | 스텝을 2차에서 확정한다 (계획) | **스텝 109개 확정 · 초안 표시 없음** |
| 자동 테스트 | EditMode 21개 | **유니티 에디터 테스트 21개** |
| 결함 리포트 | 양식 + 예시 | 그대로 |

**재현성 칸이 가장 크게 바뀐다.** 1차 때는 *"엑셀 스텝 열이 109칸 전부 비어 있다"* 가
약점이었고, 지금은 **확정된 산출물**이다.

```
제출물에 남아 있던 유일한 미확정 표시를 뗌
```

### 5쪽 · 업무 프로세스 — 2차를 붙인다

지금은 1차만 그려져 있다. **차수가 둘이 되면서 흐름이 닫힌다.**

```
계획 → TC 작성 → 1차 수행 → 결함 리포트 → 수정
                      ↓
                  2차 수행 ─── 회귀 확인
                             └─ 스텝 확정
                             └─ 1차 판정 검증   ← 이것이 포인트
```

**세 번째 가지가 이 덱의 차별점이다.** 보통 2차는 "고친 걸 다시 본다"로 끝나는데,
여기서는 **1차 자체의 오판 셋을 잡았다.**

### 3쪽 · 게임 소개

```
+ 대상 빌드 v1.0 제출본 / v1.1 수정 반영본
+ "런" 정의 한 줄 (위 1번 참고)
```

### 14쪽 · TC 구성 — 결과 열이 둘이 됐다

```
결과 열 둘 — [결과]는 최신 차수, [1회전 결과]는 이력
같은 줄에서 수정 전후가 보임. 집계와 그래프는 [결과]를 셈
```

**왜 앞에 끼우지 않았는지**를 한 줄 붙이면 좋다 — 집계 수식 59곳과 조건부 서식이 전부
`H` 열을 보기 때문에, 앞에 넣으면 전부 어긋난다. 이런 것이 실무 감각으로 읽힌다.

## 4. 쪽 번호 재부여

> 피드백 `1 2 페이지 인덱스 빼기 3 부터 시작`

```
1쪽 표지     번호 없음
2쪽 목차     번호 없음
3쪽부터      1, 2, 3 …  (17쪽 = 15)
```

**15장을 손으로 다시 박는다.** 쪽 번호가 도형에 박힌 고정 텍스트라 자동으로 안 따라온다.
3번 작업에서 쪽이 늘거나 줄 수 있으므로 **반드시 그 뒤에 한다.**

## 5. 목차에 페이지 기입

> 피드백 `목차 - 몇 페이지에 있다 쓰기`

4번이 끝나야 쓸 수 있다. 섹션 번호와 새 쪽 번호를 나란히 둔다.
