### 중요도를 이렇게 나눈 근거

**Major 셋은 전부 "읽을 수 없다"에 해당한다.** 동작은 하는데 화면이 정보를 전달하지 못한다.

- `#153` 영어 사용자는 재시작 방법을 읽을 수 없다. 번역은 되어 있고 배치만 깨진다
- `#150` 보스 패턴은 `interruptible: 0` 이라 시작되면 못 끊는다. **예고가 유일한 회피
  신호인데 그것이 안 보인다**
- `#149` 보상이 적용된 뒤에도 패널이 남아 아직 안 고른 것처럼 보인다. 다만 재선택은
  막혀 있어(`resolved` 플래그) 데이터는 어긋나지 않는다 — 그래서 Critical 이 아니다

**Trivial 둘은 동작에 영향이 없다.** 그래도 남긴 이유는 `#154` 쪽이 분명하다 — 매 실행마다
뜨는 오탐 경고가 있으면 **진짜 배선 누락이 같은 줄에 섞인다.** W3 에서 `HurtBox.health`
미배선을 놓친 것이 그 종류였다.

## 이번 회전에서 드러난 것

### 1. 실패 일곱 중 셋이 캡처와 로그에서 나왔다

`TC-UI-12`(보상 카드 정렬) · `TC-UI-13`(결과 화면 겹침) · `TC-BLD-10`(오탐 경고)은 **수행
목록에 없던 항목**이다. 플레이 중에는 눈이 다음 조작에 가 있어 화면 구석과 로그를 안 본다.

**정지된 화면과 로그를 따로 보는 절차가 필요하다.** 2회전에서는 세션마다 캡처 검토와 로그
확인을 별도 단계로 넣는다.

### 2. TC 자체의 결함이 셋 나왔다

| | |
|---|---|
| 존재하지 않는 조작을 묻는다 | `TC-EDGE-22` — 전투 씬에는 언어 항목이 없다 |
| 한 항목이 두 대상을 본다 | `TC-EDGE-23` — HUD 는 통과, 설정창은 실패 |
| 규칙이 다른 둘을 묶었다 | `TC-ENM-03` — 잡몹은 끊기고 보스는 안 끊긴다 |

**수행은 제품만 검사하는 게 아니라 TC 도 검사한다.** 셋 다 코드에서 경계를 뽑을 때 씬별·
대상별 차이를 안 본 데서 나왔다.

### 3. 한 화면만 고치고 같은 축의 다른 화면을 안 훑었다

영어 문자열이 한국어보다 1.4~1.9배 길다는 문제를 최종 빌드에서 잡아 고쳤는데, 고친 것은
**시작 화면 하나**였다. 결과 화면에서 같은 것이 다시 나왔다(`#153`).

원인이 "문자열 길이"처럼 **전역적인 축**일 때는 고친 화면 말고 같은 축에 놓인 다른 화면을
함께 훑어야 한다.

### 4. 환경이 첫 실행 상태가 아니었다

효과음이 0 으로 시작해 결함인 줄 알았는데, 레지스트리에 저장된 이전 값이었다. 코드 기본값은
1 이다. **결함으로 올리기 전에 원인을 가른 것**이 맞았고, 그 과정에서 `TC-UI-10`(첫 실행
기본값)이 새로 생겼다.

저장되는 값(해상도 · 화면 모드 · 언어 · 볼륨)은 **기존 환경과 첫 실행 환경에서 결과가
다르다.** 2회전에서는 첫 실행 경로를 처음부터 포함한다.
